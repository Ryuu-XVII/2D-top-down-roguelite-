# Night Watch (v0.2) — Guardrails, frozen contracts and instant crunch

[← Roadmap overview](../ROADMAP.md)


**Goal:** Make the keep safe to change before ~100 epics touch it. That means CI on every push, a two-to-three-week contracts sprint that freezes every shared interface, one canon and ownership table, a frozen thumb-zone action set, build flags with archived builds, and crash-safe versioned saves. In parallel, players get hit-stop, cartoon deaths and forgiving controls.

**Demo moment:** You crit an Axe Armor. The frame freezes for a heartbeat, the armor bursts apart and its helmet rolls across the red carpet, and the dash you pressed a moment too early fires exactly when it should.

**Why now:** Every later epic edits world.ts (1,055 lines), app.ts (871) or enemyAi.ts (512). Without CI, frozen contracts, flags and a canon, the backlog's ~25% duplication turns into parallel rewrites and rename churn. UX-9 has to finish before Intent v2 freezes. TEC-4 lands now because about 8 epics want save v2 and the curse-persistence bug is live. ART-1 and BAL-5 need only FxSink v2 and the time arbiter, so a second developer ships visible feel improvements while the contracts sprint runs.

**Estimate:** ~9 weeks

**Exit criteria:**

- [ ] The PR CI tier finishes in under 10 minutes: typecheck, vitest, build, gzipped bundle < 1 MB with per-domain KB budgets, a ban on raster and audio files, content validation, and a CPU-throttled (4x) tick gate of ≤ 4 ms for 140 enemies. Merges to main auto-deploy to GitHub Pages.
- [ ] The GOV-1 contracts are merged and codemodded across the codebase: Intent v2 (≤ 6 actions, per UX-9), FxSink v2 (numbers not strings, colour token ids, hitStop/impact/death), a WorldEvent catalog, an append-only stream registry in core/rng.ts, Uint16 content ids, HazardStore at 128 slots, Uint16 projectile flags, a RunHeader, and a single time-scale arbiter in core/loop.ts. Each one has an ADR and a CODEOWNERS entry.
- [ ] src/canon.ts exists and CI rejects any player-facing name not registered in it. The reconciliation ADR settles one pet roster, one mentor, one true-ending macguffin, one heat ladder, canonical biome and boss names, and the 'Grimoire', 'Curtain Call' and 'Relic' collisions. Every name has an ipRisk rating, and a system-ownership table names one owner epic per store, registry, save section and stream.
- [ ] UX-9 layouts are validated by 3+ testers on a 5.5-inch phone and an 8-inch tablet: ≤ 4 on-screen touch buttons, and every action reachable on touch, gamepad and keyboard/mouse.
- [ ] Saves use a versioned, checksummed envelope with A/B writes and a migration registry with fixture tests. Killing the tab mid-write loses at most the current room. The used Sanctuary fire and active curses survive continue-run.
- [ ] Build-time flags let unfinished features merge dark. Every deploy is archived immutably. The service worker never swaps builds mid-run, and a downgrade guard refuses saves written by a newer build.
- [ ] Hit-stop and family-specific cartoon deaths exist for all 7 enemy types and are presentation-only: sim hashes are identical with hit-stop on and off. The input buffer and dash grace are tick-defined sim rules with replay tests.

#### TEC-1 · 1. Night Watch CI: quality gates, golden screenshots and GitHub Pages deploy

*Engineering, performance, platform & tooling · effort M · impact 5/5*

Before a month of refactors and four new floors go into the keep, check every push: typecheck, tests, build, the 1 MB budget, a ban on raster or audio files, content validation, golden screenshots of the Castle Gate and Count Vlador's throne, and a perf gate on the 120 Hz tick. Every merge to main deploys to GitHub Pages. **Player value:** Broken builds and visual regressions (lost ink outlines, a broken HUD heart pill, a missing Rune Colossus spiral) are caught before players see them. The game also gets a stable, offline-capable URL to install from on any phone or PC.

- **Core pipeline (ci.yml)** — Run typecheck, tests and build on every push and PR, and make the run a required status check on main.
  - *Implementation:* Add .github/workflows/ci.yml: ubuntu-latest, Node 22, actions/setup-node with npm cache, npm ci, npm run typecheck, npm test -- --reporter=default --reporter=junit, npm run build, then upload dist/ as an artifact. A concurrency group cancels superseded runs. Add package.json scripts check:budget, check:assets, lint:determinism and ci (all checks chained). Tools run with vite-node (made an explicit devDependency).
  - *Acceptance:* A PR with a strict-mode TS error fails at the typecheck step in under 3 minutes. A green run uploads a dist artifact. Total wall time for the job is under 6 minutes. Branch protection requires the check.
- **Bundle budget gate** — Enforce the < 1 MB gzipped rule with per-chunk budgets and a size delta comment on each PR.
  - *Implementation:* tools/check-budget.ts reads dist/assets/*, gzip -9 and brotli-compresses each file, and compares the totals against budget.json. Budgets: total gz <= 900 KB (hard fail at 1 MB), initial path (index + css + WebGLRenderer + RenderTargetSystem + browserAll) <= 300 KB gz (about 225 KB today), each lazy chunk <= 120 KB. A markdown table goes to $GITHUB_STEP_SUMMARY, and actions/github-script posts the delta against main's stored baseline artifact.
  - *Acceptance:* Adding a 200 KB dependency fails the build and names the offending chunk. The summary shows today's figures (~174 KB index, ~255 KB total). The dev console and Device Lab lazy chunks are reported as lazy and stay out of the initial-path budget.
- **Zero-raster asset guard and import boundaries** — Enforce the '100% code' rule and keep the sim headless.
  - *Implementation:* tools/check-assets.ts walks git ls-files. It fails on raster, audio, model and font extensions (png jpg gif webp avif ico wav mp3 ogg flac glb gltf fbx ttf woff2 ...) and on magic bytes for extensionless or renamed files (89504E47, FFD8FF, RIFF..WAVE, OggS, ID3, glTF). It also scans dist/ against an allowlist of build-generated icons from Epic 8. An import-boundary check, built on the TypeScript compiler API that is already a devDependency, rejects any import from render/, ui/, platform/, audio/ or pixi.js inside src/game, src/gen or src/core.
  - *Acceptance:* Committing bat.png, or a WAV renamed to bat.dat, fails the guard. Adding import { Graphics } from 'pixi.js' to src/game/enemyAi.ts fails with 'sim must stay headless'.
- **Content validation suite** — Catch broken references between cards, items, events, enemies, icons and art before runtime.
  - *Implementation:* tests/content.test.ts checks: unique ids across CARDS (27), ITEMS (21), events (5) and ENEMY_DEFS (10). Every HookKey is implemented, via an exported HOOK_IMPLEMENTED satisfies Record<HookKey, true> in playerCombat, so a missing hook becomes a compile error. Every card icon and item glyph exists in the icons.ts registry. Every event 'card' effect id resolves in CARD_BY_ID. Each floor's spawn table is non-empty, and its cheapest enemy is <= baseBudget x floorDifficulty. BOSS_FOR_FLOOR covers CONFIG.floors. Prices strictly increase with rarity (cards 30<45<70<110, items 35<55<85<130). xpReq is monotonic up to L50. A plain ENEMY_ART_KEYS const exported from shapes.ts covers every def key and ENEMY_HEIGHT.
  - *Acceptance:* Adding card 'garlic_aura' with icon 'garlic' that is not drawn in icons.ts fails with 'card garlic_aura: icon garlic missing'. Removing the Gargoyle's art key fails. The suite runs in under 1 s.
- **Playwright cross-engine smoke tests** — Run end-to-end flows on Chromium, Firefox and WebKit with keyboard+mouse, touch and gamepad.
  - *Implementation:* Add @playwright/test as a devDependency, with specs in tests/e2e/. Projects: desktop 1920x1080 on all 3 engines, Pixel 7 (touch), iPad Mini landscape (touch). Flows: title tap, class select Vector Vanguard, start room, walk east through a door, fight, pause tabs (Character/Equipment/Cards/Map/Settings), abandon, game-over screen. Dual touch sticks are driven with CDP Input.dispatchTouchEvent. The gamepad flow stubs navigator.getGamepads via addInitScript (standard mapping, D-pad + A/B). Tests run against vite preview of dist.
  - *Acceptance:* All 5 projects pass in CI. A failure uploads trace.zip and video. The job finishes in under 10 minutes. Switching input method mid-run (key, then touch, then pad) is covered by one spec.
- **Golden render mode and screenshot diffs** — Make rendering deterministic so pixel diffs catch art and HUD regressions.
  - *Implementation:* Add a ?golden=1 flag. GameLoop is stepped manually (window.__ck.step(n) runs exactly n sim ticks and renders at a fixed frameDt of 1/60). Every renderer Math.random (shake, burst spread, trails, text jitter, lightning jitter, roomView torch phases) is replaced by a seeded cosmetic Rng(0xC0FFEE). Shake, flash and PerfMonitor are off; DPR 1, preset high, WebGL forced. The job runs only inside the pinned mcr.microsoft.com/playwright Docker image so the BitmapFont system fonts are identical between runs. Scenes: Castle Gate start room at tick 0; a Bone Catacombs elite room with an elite Axe Armor mid-windup; Rune Colossus enrage at 40% HP; Count Vlador's hellfire fan; a level-up tarot screen offering Holy Cross, Storm Chain and Whetstone; the shop; the HUD showing '7.1k / 7.1k'. Assertions use toHaveScreenshot({ maxDiffPixelRatio: 0.002 }), and npm run golden:update rebaselines.
  - *Acceptance:* Two consecutive CI runs produce pixel-identical screenshots. Changing OUTLINE from 3 to 2 in pen.ts fails all 7 scenes. Updating baselines takes one documented command.
- **Perf regression gate** — Stop simulation and generation slowdowns before they ship.
  - *Implementation:* Move tests/perf.test.ts to vitest bench plus tools/perf-gate.ts. Measure the median of 5 runs of: the 150-enemy heavy tick, a 60x40 combat room (BSP + A* + CA + Poisson), and a full 3-floor graph-plus-rooms build. Compare against a committed perf-baseline.json, which is updated only on PRs labelled perf-baseline-update. Fail when a result exceeds baseline x 1.3 or the 2 ms desktop tick budget. Write the trend to the step summary.
  - *Acceptance:* Replacing spatial-hash separation with an O(n^2) loop fails the gate. Normal runner noise (±15%) passes 20 of 20 reruns.
- **GitHub Pages CD and PR previews** — Deploy main to Pages and give each PR a preview build that works on phones.
  - *Implementation:* deploy.yml runs on pushes to main: build, actions/upload-pages-artifact, actions/deploy-pages. base './' is already relative, so the build works under /2D-top-down-roguelite-/. A second job publishes PR builds to the gh-pages branch under /pr/<n>/, comments the URL on the PR, and prunes it when the PR closes. The SW cache name comes from a content hash (Epic 8), so previews don't evict each other.
  - *Acceptance:* Merging to main serves the new build at https://ryuu-xvii.github.io/2D-top-down-roguelite-/ within 5 minutes. After installing the PWA from Pages and going offline, it still boots to the title screen. The PR preview URL works on a real phone.

**Depends on:** Golden scenes deep inside a run become trivial once TEC Epic 3 replays and Epic 2 dev commands exist; until then, scenes are reached with ?autostart and scripted spawns; ART and UI must rebaseline goldens on intentional visual changes (documented golden:update flow); TEC Epic 8 PNG icons extend the asset-guard allowlist for dist/
**Risks:** Screenshot flakiness from font rasterization and GPU differences. Mitigation: pinned Playwright Docker image, SwiftShader, seeded cosmetic RNG, small diff tolerance; Shared GitHub runners are noisy for perf gates. Mitigation: medians, relative thresholds, render perf report-only; Service-worker scope and path issues under the Pages subpath and the /pr/<n>/ previews
**Constraint check:** Every tool is a devDependency (Playwright, vite-node) or a script under tools/, so the shipped bundle gains 0 bytes. The asset guard makes the zero-raster/zero-audio rule mechanical. Golden mode is gated behind a URL flag and touches only the render layer's cosmetic RNG, so sim determinism is untouched. WebKit, Firefox and touch/pad projects cover the cross-platform promise.

**Review notes:**
- *feasibility* (keep, effort L): Must land first. Cross-engine Playwright, golden screenshots, a perf gate and PR previews under a service-worker scope is L. Add a phone-calibrated (CPU-throttled) tick budget to the perf gate.
- *player* (keep): Schedule first; every refactor epic leans on it. Add per-domain bundle-byte budgets, since text, cards and art growth threaten the 1 MB gzip cap.
- *completeness* (keep): Build first; everything gates on it. Plan for CI minutes, since nightly fuzz, bots and a Playwright cross-engine matrix on free runners can exceed quotas.

#### GAP-1 · GOV-1 Keystone Contracts: Intent v2, FxSink v2, WorldEvent catalog, stream and content-ID registries, RunHeader

*Gaps found in review · effort L · impact 5/5*

A two-to-three-week contracts sprint, run before any domain branches, that freezes every interface more than one epic wants to change. Then one mechanical migration week moves the codebase onto them with codemods. Lightweight governance (CODEOWNERS, ADRs, append-only registries, a hot-file calendar) keeps the contracts frozen afterwards. **Player value:** Indirect but large. Content arrives sooner and with fewer regressions. Damage numbers and effects stop allocating, which removes hitches on phones. Replays, dailies and challenge codes change format once, not five times.

- **Intent v2: packed action bitfield** — Replace the four booleans with held and pressed u16 bitmasks over the UX-9 action charter (ATTACK, DASH, SKILL, ULT, SUBWEAPON, INTERACT, SWAP, plus reserved bits). Replace the aimAssist and autoAim booleans with an aimMode enum (free, assist, auto). Quantize move and aim before the sim reads them, so live play and tape playback see identical values.
  - *Implementation:* src/game/intent.ts: ActionBit const, IntentV2, and packIntent/unpackIntent to a record of 16 bytes or less (u16 held, u16 pressed, i8 moveX/moveY, u16 aim angle, u8 aimMode, two i16 aim-point coordinates). src/platform/input.ts: the latch{} object becomes bit operations, with quantization in sample(). src/game/playerCombat.ts and player.ts read the bits. A legacy emptyIntent() adapter keeps tests/sim.test.ts and perf.test.ts compiling during the migration.
  - *Acceptance:* 10,000 random intents round-trip pack and unpack byte-identically. Driving World with raw intents and with packed-then-unpacked intents gives the same state hash after 5,000 ticks. A test checks that every ActionBit has a KB+M, gamepad and touch binding in the UX-9 table. No booleans remain on Intent.
- **FxSink v2 and sim-side time authority** — Colours become palette Tok indices, which ART-2's colourblind remap and BIZ-1's blood toggle need. damage(x, y, amount, flags) replaces text(string). sfx takes a u16 SfxId from the registry instead of a closed union. Hit-stop and slow-motion move out of app.ts (loop.timeScale = 0.35 / 0.3) into a deterministic World.timeCtl counted in ticks; the sink only observes it.
  - *Implementation:* src/game/fx.ts: FxSinkV2, NullFx, and RecordingFx for tests. src/render/fxSink.ts adapts to it. src/theme.ts exports a Tok enum and a TOK_RGB table. world.ts:482/591/627 switch to fx.damage. The renderer gets a numeric glyph writer for bitmap damage numbers, with no string concatenation. World.timeCtl holds {freezeTicks, slowTicks, slowScale}; app.ts reads it for presentation only.
  - *Acceptance:* A lint rule fails on 0xRRGGBB literals and on fx.text( in src/game. RecordingFx records zero string arguments during the 600-tick heavy perf test. Death and boss-kill slow-mo give the same state hash at 60, 120 and 144 Hz render rates. The heavy tick stays at or under 0.35 ms in Node.
- **WorldEvent catalog v1 and zero-alloc event ring** — A versioned, append-only catalog of every event the sim sends to the app: today's 7, plus reserved IDs for planned ones (hit, kill, statusApplied, parry, perfectDodge, pickup, hazardTriggered, secretFound, bossPhase, subweaponThrown, petLevel). Events are written into a preallocated ring of fixed-width records. Gameplay side effects that app.ts performs today, such as w.spawnBossRewards() on bossDefeated, move into World.
  - *Implementation:* src/game/events.ts: an EventId const documenting owner and payload, and an EventRing of Int32Array/Float32Array columns holding 256 events per tick. world.ts emits into the ring, and app.ts handleEvents iterates it (a TEC-2 bus adapter subscribes later). tests/contracts.test.ts snapshots the IDs against contracts/events.json.
  - *Acceptance:* Removing or renumbering an ID fails the catalog test. Emitting 10,000 events allocates nothing (heap delta under 64 KB with --expose-gc). A grep test confirms app.ts handleEvents no longer mutates World. The boss and level-up flows pass the existing sim smoke tests.
- **STREAM registry and content-ID registry** — One append-only table of PRNG streams, each with an owner epic, a purpose, the epoch it was introduced in, and reserved blocks per domain. The ad-hoc salts (graph 0x6a09e667, room sim 0xc0b4a7, card offers in app.ts:605, altar rolls from Math.floor(roll*1e6)) are kept as named legacy aliases until GOV-2 retires them. A second registry gives enemies, bosses, cards, items, hazards, projectiles and SFX stable numeric IDs.
  - *Implementation:* src/core/streams.ts defines STREAM blocks: GEN 1-15, ENM 16-31, BLD 32-47, CLS 48-63, STO 64-79, MET 80-95, SOC 96-111, presentation-only 200+. Content IDs live in src/content/ids.ts. EnemyStore.def becomes a Uint16Array. The card-offer RNG moves from app.ts into src/game/cards.ts and uses STREAM.cards. scripts/check-registries.ts runs under vitest.
  - *Acceptance:* CI fails if a stream or content ID is removed or renumbered, or if `new Rng(hashCombine(` appears outside src/core with a literal salt that isn't registered. A grep test confirms the card-offer seed is derived in src/game. Allocating 300 enemy IDs does not overflow.
- **Store layout v2 headroom** — Resize the SoA stores once, ahead of BIO-3, GEN-5, BLD-2, ENM-2, CLS-2 and SOC-6, so those epics don't each widen them. Hazards grow to 256 slots and gain owner, team, shape, angle, w/h and u16 flags columns. Projectile flags become u32. Enemies get reserved columns for a status bitset, affix mask, aiId and owner (for pets and co-op).
  - *Implementation:* src/config.ts: POOLS.hazards goes from 64 to 256. src/game/stores.ts: the new columns plus a HazardShape enum (circle, rect, cone, ring). ProjectileStore.flags becomes Uint32Array. EnemyStore gains status (Uint32Array), affix (Uint16Array), aiId (Uint16Array) and owner (Uint8Array). The hazard update in world.ts dispatches on shape.
  - *Acceptance:* With 160 enemies, 256 live hazards and 600 projectiles, the heavy perf tick stays at or under 0.5 ms in Node. A test measures total store memory at 600 KB or less. Existing HAZ kinds behave identically: the sim smoke tests and boss-pattern test pass.
- **RunHeader and composite build fingerprint** — One struct records every input that decides a seed's outcome: epoch, sim ABI, content hash, balance version, ruleset ID, run seed, attempt, daily key, class, aimMode and assists, flag mask, mod hash, and a snapshot of meta inputs (statBonus, packs, unlocks, journey mask). A single build fingerprint replaces the separately planned GEN_VERSION, generation epoch, BALANCE_VERSION, ABI and contentHash.
  - *Implementation:* src/game/runHeader.ts encodes the header to 32 bytes plus a base32 label. vite.config.ts hashes src/game, src/gen and src/content into contentHash and injects __BUILD__. run.ts toSave/fromSave embed the header, and meta.ts SeedRecord gains one. TEC-3 tapes, SOC-2 links, MET-7 dailies and the REL-1 SW cache name all use the same struct.
  - *Acceptance:* The header round-trips through encode and decode. Editing any file under src/gen changes contentHash; a CSS change does not. In a fixture test, a RunSave with a different epoch or ABI goes through the documented stale-run path instead of silently continuing.
- **Governance kit and mechanical migration week** — CODEOWNERS for the hot files (world.ts, enemyAi.ts, playerCombat.ts, app.ts, config.ts, stores.ts and the registries). An ADR folder seeded with five decisions: event bus, save registry, command layer, time authority and stream allocation. A hot-file integration calendar and PR size rules. One scheduled week in which codemods move every call site onto the new contracts: FxSink v2, colour tokens, fx.damage, scrap renamed to gems, and killer ID on damage.
  - *Implementation:* .github/CODEOWNERS; .github/pull_request_template.md with a contract-touch checkbox; docs/adr/0001-0005; scripts/codemods/*.ts using ts-morph as a dev dependency only; a CI job that requires an ADR reference whenever contracts/* or src/core/streams.ts changes.
  - *Acceptance:* After each codemod, npm run typecheck and npm test pass. CI rejects a PR that edits contracts/events.json without an ADR link. When the migration week ends, a grep finds no `scrap` identifiers left in src/.

**Depends on:** TEC-1 Night Watch CI (CI gates); UX-9 Thumb Zone Charter (action list for Intent v2); TEC-2 Keep Kernel (bus adapter over the event ring); TEC-3 Chronicle of Blood (consumer of Intent v2 and RunHeader)
**Risks:** Freezing too early can lock in the wrong abstractions. Mitigate with reserved bits and ID blocks, plus an ADR-gated amendment process.; The migration week will conflict with branches in flight. Schedule it while only foundation branches are open.; Quantizing intents could subtly change aim feel. A u16 angle step is about 0.0055 degrees, below what players can perceive, but run a feel check.
**Constraint check:** Pure TypeScript types, typed-array columns and build scripts, with no assets. Packed intents and the event ring remove per-tick allocations instead of adding them. Stores grow by about 200 KB of typed arrays, and the bundle by under 4 KB gzipped. Every RNG stream and version input becomes explicit, which strengthens determinism. Nothing is platform-specific.

#### GAP-3 · UX-9 Thumb Zone Charter: one frozen action set and per-device control layouts

*Gaps found in review · effort M · impact 5/5*

Fix the full gameplay action set once, at six actions at most, and design the touch, gamepad and KB+M layouts before any epic adds a button. A new mechanic has to fit an existing slot through timing, context or a hold, or replace one. Validate the layouts on real 5.5-inch phones and 8-inch tablets. **Player value:** Phone players get controls that two thumbs can actually play, without a seventh button crammed under the right thumb. There is one clear 'super' moment instead of two competing ones, and the controls feel the same on every device.

- **Action Charter** — A data table of the six gameplay actions, each with an owner, plus the default resolution for every epic's request. Attack: auto-fire on the aim stick, and holding it is BLD-8's charge. Dash: BLD-4's parry and perfect dodge become timing windows on Dash, not a new button. Skill: CLS-1's A1. Ultimate: CLS-1's Ult; BLD-3's 'Item Crash' becomes the Ult variant when a sub-weapon is equipped, so there is a single super. Sub-weapon: BLD-3's action, which on touch is a button on the thumb arc and also a swipe-up on Dash. Interact: contextual, and also covers BLD-8's weapon swap when picking a weapon up. CLS-1's A2 becomes a hold on Skill or a loadout choice (CLS-6), not a seventh button. UX-4 toggles and SOC-7 photo mode live in the pause menu.
  - *Implementation:* src/game/actions.ts defines ActionId, the press grammar, default bindings per device and the owning epic. docs/adr/0006-action-charter.md records the CLS-1, BLD-3, BLD-4 and BLD-8 resolutions. GOV-1 generates the Intent v2 bits from this table.
  - *Acceptance:* A test asserts at most 6 gameplay actions, every action bound on all three devices with no default conflicts, and every planned epic action mapped to a charter slot. The CLS-1, BLD-3, BLD-4 and BLD-8 owners approve the ADR before any of them adds input code.
- **Touch layout v2: thumb-arc cluster and exclusion zones** — Today three loose buttons share the right half of the screen with the floating aim stick. Replace them with an arc cluster around the bottom-right corner: Dash nearest the thumb, Skill and Sub-weapon along the arc, Interact appearing above the arc only when it applies, and Ult on the HUD gauge pill, which glows and becomes tappable only when full. The aim stick spawns only outside the buttons' exclusion circles, and every layout mirrors for left-handed play.
  - *Implementation:* src/ui/touchLayouts.ts is pure geometry: slots in rem from the safe-area corner, with three size classes (phoneS, phoneL, tablet) picked from the viewport's short edge in CSS px. hud.ts layoutTouch consumes it. input.ts onPointerDown checks the exclusion circles before claiming the aim stick. styles.css sets .tbtn sizes to at least 48 CSS px.
  - *Acceptance:* A pure geometry test covers 6 viewports (iPhone SE 375×667, iPhone 15 393×852, Pixel 7a 412×915, Galaxy A12 720×1600 at DPR 2, iPad mini 744×1133, Galaxy Tab A8 800×1280) in both orientations and both handedness modes. In every case each target is at least 48 px, nothing overlaps, everything sits inside the safe area, and every target is within 0.45 × the short edge of the thumb corner. A unit test confirms a pointerdown inside an exclusion circle never starts the aim stick.
- **Press grammar measured in ticks** — Each action declares tap, hold, release or toggle semantics, with thresholds in sim ticks rather than milliseconds, and every hold has a toggle alternative (UX-4). The swipe-dash on the move stick, currently a wall-clock check under 200 ms in input.ts, moves to ticks so it behaves the same at any frame rate.
  - *Implementation:* Press specs live in actions.ts. input.ts runs a state machine per action that emits held, pressed and released bits. settings.ts adds a holdToToggle option per action.
  - *Acceptance:* Unit tests with a fake clock show synthetic pointer sequences producing identical bits at 30, 60 and 120 FPS. A test enumerates the hold actions and confirms each has a toggle variant.
- **Canonical gamepad and KB+M layouts with glyph slots** — Defaults keep today's muscle memory: Space or RMB for Skill, Shift for Dash, E for Interact, with Q added for Sub-weapon and R for Ult. Gamepad: right stick aims and fires, RT attacks, A Skill, B Dash, X Interact, Y Sub-weapon, and LB+RB or LT for Ult. The table feeds UX-3 remapping and the HUD prompt glyphs.
  - *Implementation:* Default bindings live in actions.ts. input.ts pollGamepad and onKeyDown read from that table. hud.ts generates its abilityKey and dashKey labels from the table instead of hard-coded 'SPACE' and 'A'.
  - *Acceptance:* A grep finds no hard-coded key strings left in hud.ts. Remapping one binding updates every prompt that shows it. A snapshot test confirms Steam Deck, Xbox and PlayStation layouts show the correct glyph set.
- **Contextual reduction rules** — Use context to cut the button count. Gems, hearts and sub-weapon ammo auto-collect through the existing magnet. Interact appears only for chests, shrines, NPCs, altars and ground weapons. Weapon swapping happens by interacting with a ground weapon, and pet commands are automatic.
  - *Implementation:* world.ts nearInteract already exists; InteractKind gains ground weapons and NPCs. hud.ts shows tInteract only while nearInteract ≥ 0. A function in touchLayouts.ts maps each game state to its visible buttons.
  - *Acceptance:* A test enumerates game states (combat, near a chest, boss fight, sub-weapon empty, Ult ready) and confirms no state shows more than 5 gameplay buttons plus the pause gear.
- **Real-device validation protocol and local touch heatmap** — Eight testers per size class, on real 5.5–6.1-inch phones and 8-inch tablets, run scripted tasks: dash through a boss bullet fan while casting Skill, fire Ult within 1 s of the gauge filling, and interact during combat. #### BAL-5 · Velvet Controls: feel tuning

*Game design, balance & difficulty · effort M · impact 4/5*

Make the controls responsive and forgiving: buffered inputs, a forgiving dash, aim assist that helps without taking over, and impacts with weight. **Player value:** No more 'I pressed dash!' deaths. Touch and gamepad players get help that still feels like their own skill, and crits and kills feel as chunky as the cartoon art.

- **Input buffer** — Dash, ability and interact presses are held for 150 ms (18 ticks) and fire on the first tick they become legal, instead of being dropped when pressed slightly early.
  - *Implementation:* Player gets bufDash, bufAbility and bufInteract tick counters inside the sim. updatePlayer sets them on an intent edge and consumes them in the dash/ability blocks of playerCombat.ts. They live in the sim, so replays of the Intent stream stay deterministic.
  - *Acceptance:* Unit tests: dash pressed 10 ticks before the cooldown ends fires on the first legal tick; pressed 30 ticks before, it is dropped; an ability waits through an energy shortfall of up to 150 ms. Bot telemetry shows zero dropped dashes.
- **Dash grace and graze** — Direction grace: if the move stick was released up to 80 ms before the dash (a thumb lifting on touch), the dash uses the last move direction instead of the aim. Graze: a hostile projectile passing within 14 px during i-frames gives +6 energy (at most 5 grazes per second), with a gold sparkle and a bell tick.
  - *Implementation:* playerCombat.ts dash block keeps lastMoveX/Y and the time since; world.updateProjectiles adds the graze test to the existing distance check for hostile shots.
  - *Acceptance:* Unit tests for direction grace and the graze cap. The graze test adds no measurable tick time in perf.test.
- **Aim assist 2.0** — Replace the hard snap with scored targeting: angle/cone + 0.3 x distance/range, line of sight required, a 150 ms lock to stop flicking between targets, and a partial blend toward the target (touch 0.65, gamepad 0.45, mouse 0). One-thumb auto-aim prioritizes ranged enemies winding up, then charging Axe Armors, then the nearest enemy, and shows a target ring.
  - *Implementation:* playerCombat.ts aim section: add w.los to the cone candidates and keep assistTarget/assistLockT on Player. CONFIG.aimAssist {cone, blend per device, lock}. Strength slider in settings.ts.
  - *Acceptance:* Unit tests: the target switches between two equidistant enemies at most once per 150 ms; enemies behind walls are never selected; mouse aim is unchanged at strength 0.
- **Hit-stop that keeps replays identical** — Brief freezes on impact: none for normal hits, 25 ms on a crit, 50 ms on an elite kill, 90 ms on a boss phase change, 140 ms on a boss death. A budget limits freezes to 8% of wall-clock time per second, so a Requiem nova on 30 bats does not stutter. Turned off with reduced motion.
  - *Implementation:* core/loop.ts gets hold(ms), which pauses accumulating ticks without changing world state; inputs during the freeze wait in the input buffer. The FxSink emits a hitstop event and app.ts forwards it to the loop.
  - *Acceptance:* A replay hash is identical with hit-stop on and off. A frame-time trace shows the 8% budget is respected.
- **Movement tuning and corner slide** — Split acceleration and deceleration (about 0.07 s to 90% speed, about 0.05 s to stop) instead of one shared constant. When the player is blocked on one axis by 8 px or less of a tile corner, nudge along the free axis so they stop snagging on corridor corners. Knockback on the player drops from 260 to 200 px/s so a hit does not bounce them into a second enemy.
  - *Implementation:* playerCombat.ts movement block; a player-only nudge in world.slide; CONFIG.move {accel, decel, cornerAssistPx}.
  - *Acceptance:* Unit test: a player moving diagonally into a corner offset by 6 px slides past. A corridor traversal-time test passes.
- **Knockback weight and stagger** — Enemy weight classes: light (Blood Bat, Skeleton, Bone Archer) take 1x knockback; medium (Ghoul, Hex Witch, Gargoyle) 0.7x; heavy (Axe Armor) 0.35x but staggers for 0.4 s after taking 60 damage within 1 s. Elites take 0.5x with the same stagger rule. Bosses keep 0.08x and gain a stagger meter that opens the Colossus core window.
  - *Implementation:* enemyDefs.ts weight and poise fields; world.hitEnemy uses them instead of the hard-coded kbScale; EnemyStore gets a poise accumulator.
  - *Acceptance:* Data-driven unit tests per weight class. Bot TTK changes by at most +/-10%.

**Depends on:** needs the tooling team: loop.hold() in core/loop.ts; needs UI: aim-assist strength slider and target ring; needs AUD: graze tick and crit/kill impact sounds; needs Platform: haptic pulses on graze and hit-stop
**Risks:** Strong aim assist trivializes touch play; tune per device with bot and human data; Hit-stop can feel laggy at 120 Hz on 4K; keep the budget and honor reduced motion; Corner slide could let players clip through doors; restrict it to TILE_WALL corners
**Constraint check:** Buffers are tick counters on Player inside the deterministic fixed-dt sim. Hit-stop freezes wall-clock time only, so the sequence of sim states and replays is identical. Aim assist reuses the spatial hash query plus one line-of-sight check per tick. Touch, gamepad and keyboard/mouse share the Intent path. About 2 KB gzipped, no assets.
