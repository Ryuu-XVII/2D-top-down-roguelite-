# Keep Kernel (v0.3) — Architecture, determinism, replays and an honest economy

[← Roadmap overview](../ROADMAP.md)


**Goal:** Split App and World into a kernel (typed event bus, command layer, system scheduler, content registries), make every run replayable from seed plus tape on any engine, record what actually happened (RunTally and RunRecords), and fix the economy so spending gems never costs meta-progress. Settings v2 and a local-first trust layer ship at the same time as the first untrusted imports.

**Demo moment:** You die to Count Vlador's blood spiral, open the replay on the same phone, scrub back four seconds and see exactly which bullet clipped you. Then the Soul Ledger pays you for the elites you slew, not the gems you hoarded.

**Why now:** About 40 epics edit world.ts and app.ts, so the kernel split comes before any of them. TEC-3's state hashes and stream split go first within the milestone because they are the parity gate that guards TEC-2. Tapes then build on TEC-2's command layer. MET-1 and the economy fix need the bus. TRU-1 lands with the first untrusted imports (Soul Sigil, tapes), not at launch, and its opt-in funnel lets the vertical slice measure drop-off.

**Estimate:** ~12 weeks

**Exit criteria:**

- [ ] The app.ts and world.ts split lands in slices behind sim-hash parity: 500 recorded seeds produce identical per-second world hashes before and after every slice.
- [ ] The sim/cosmetic RNG split is complete, and a lint rule bans Math.random and FX calls that consume sim streams. enemyCap and the view rect are ruleset constants, and no sim code reads the device or preset.
- [ ] A run recorded in desktop Chromium replays to identical state hashes in Firefox, WebKit and on an Android phone. A 30-minute run tape is under 200 KB, and crash reports are stored locally with their tape.
- [ ] A perf overlay (?debug=perf) shows per-system timings. Allocations per sim tick are zero (alloc-counting test), and heap stays within ±2 MB over a 10-minute bot soak.
- [ ] Souls are paid from achievements on a Soul Ledger end screen, not from hoarded gems. The boss purse is guaranteed and the shop has a reroll. Economy model tests keep gems and souls per floor inside their tuned bands.
- [ ] The schema-driven settings v2 panel has categories, presets and live previews. The Hunter's Oath first-run card takes 30 seconds or less.
- [ ] Production runs under a strict CSP. Save sigils and tapes all pass through one size-limited, fuzzed decoder, and no innerHTML sinks remain. Analytics are opt-in with no endpoint configured, and Export Diagnostics works offline.
- [ ] Playtest protocol v1 has been run with 5+ external players, and every 'that felt unfair' report carries a replay.

#### TEC-2 · 2. Keep Kernel: event bus, command layer, system scheduler and the app.ts split

*Engineering, performance, platform & tooling · effort L · impact 5/5*

Split the 871-line App god object and the 1,055-line World into a kernel the other teams can build on. It has five parts: a typed, allocation-free event bus; a command layer that turns every menu decision into data; an ordered system scheduler with typed-array component columns; content registries; and a dev console that is just a prompt for commands. **Player value:** Players get more content faster (new floors, enemies, pets, achievements) with fewer regressions. Exploits caused by UI code mutating state disappear. Every decision becomes replayable, which Epic 3 depends on.

- **Typed allocation-free event bus (core/bus.ts)** — Replace World.events object literals with a typed bus that gameplay and presentation listeners can subscribe to.
  - *Implementation:* EventBus stores events in a preallocated SoA ring (capacity 2,048 per tick): type Uint16Array, i0/i1 Int32Array, f0/f1/f2 Float64Array. Events are emitted as emit(EV.ENEMY_KILLED, def, elite, x, y). Subscribers are registered per type at boot, so no closure is created per emit. The ring is drained at two points: after each sim tick for gameplay listeners (run stats, codex, achievements) and once per render frame for presentation listeners (toasts, banners, music mood). The catalog in game/events.ts: ENEMY_SPAWNED, ENEMY_KILLED, PLAYER_HURT(sourcePattern, dmg), PLAYER_DIED, LEVEL_UP, CARD_TAKEN, ITEM_EQUIPPED, PICKUP, ROOM_CLEARED, BOSS_SPAWNED, BOSS_PHASE, BOSS_DEFEATED, INTERACT, EXIT. Boss names are looked up from def ids, not passed as strings.
  - *Acceptance:* The allocation harness (Epic 6) measures 0 bytes per emit. 10k emit+drain pairs per tick cost under 0.05 ms. Existing reactions are unchanged in Playwright smoke: the 'BOSS DEFEATED!' banner, 0.3x slow-mo for 1.2 s, 'Room cleared! The doors unseal.'
- **Command layer and headless RunController** — Every out-of-tick decision becomes a serializable command applied by headless game code. UI only renders choices and dispatches commands.
  - *Implementation:* game/commands.ts defines a small tuple-encoded union: PICK_CARD(offerIdx), ALLOC_STAT(attr), BUY(shopIdx), FORGE(slot), EQUIP_FOUND, SALVAGE_FOUND, REST, SHRINE_OFFER, RESOLVE_EVENT(choice), OPEN_CHEST(interactIdx), ENTER_NODE(target), DESCEND, ABANDON. game/runController.ts owns Run+Player+World and takes over app.ts L603-869 (cardRng, onInteract, offerItem, applyEvent, nextFloor). It exposes 'pending decision' descriptors such as {kind:'cardOffer', cards:['holy_cross','storm_chain','whetstone']} for UI to render. Each dispatch is stamped with the sim tick and fed to the replay log (Epic 3) and the dev console.
  - *Acceptance:* A new vitest runs a shop visit headless: buy a Holy Morning Star at 85 x 1.25 = 106 gems, then forge the weapon L1 to L2 for 25 gems. Final state matches the UI-driven path. grep finds no Player field writes (hp, scrap, statPoints, metaAttrs, equipment) under src/app.
- **System scheduler and World split** — Turn World.update into an ordered, profiled list of systems, and split the oversized files.
  - *Implementation:* game/systems.ts defines interface System { id; phase: 'pre'|'player'|'nav'|'enemies'|'projectiles'|'hazards'|'pickups'|'waves'|'interact'|'post'; update(w, dt) }. World iterates a frozen array: no per-tick allocation, and a fixed order keeps it deterministic. An optional profiling wrapper writes per-system ms into a Float32Array when w.profile is on. world.ts is split into game/world/{collision,flow,spawn,damage,projectiles,hazards,pickups,waves,interact}.ts, and boss code moves to game/ai/bosses/{gorehorn,colossus,vlador}.ts. Other domains can then insert systems (status effects, pets like the yellow puffball and fire imp, floor traps) without editing World.
  - *Acceptance:* The sim-hash sequence (Epic 3) is identical before and after the refactor across 50 seeded room playthroughs. The 150-enemy tick stays within ±5% of ~0.3 ms. No file in src/game exceeds 450 lines.
- **Component column registry and AI behaviour registry** — Make SoA stores and enemy AI extensible without a third-party ECS.
  - *Implementation:* core/columns.ts provides defineColumns({x: F32, hp: F32, def: U8, ...}), which generates typed arrays at POOLS capacity. Modules can register extension columns at boot, e.g. statusColumns { freezeT, curseStacks, bleedDps, markT }. ai/registry.ts maps behaviour ids to update functions. An EnemyDef can list behaviours ['chase','charger'] plus a selector, replacing the single switch (d.ai). bitecs was considered and rejected (~5 KB, and it changes iteration semantics); the existing SoA stores are already archetype tables.
  - *Acceptance:* Adding a 'frozen' status column and a system that halts movement for 1.5 s touches 0 lines in world.ts and enemyAi.ts. All 7 enemies and 3 bosses produce identical hashes. An Axe Armor variant that throws its axe when the player kites beyond 300 units can be defined in data plus one behaviour file.
- **Content registries with stable string ids** — Give enemies, cards, items, events, floors and bosses registries with stable ids.
  - *Implementation:* content/registry.ts provides a generic Registry<T extends {id: string}>: frozen at boot, assigns numeric indices (Uint8 def ids stay for SoA), throws on duplicate ids, and offers registerPack() for future packs such as a 'Clocktower of Hours' floor or a 'Silver' card pack. The hand-numbered ENEMY_DEFS ids 0..9 become registry-assigned. Saves and replays reference string ids only.
  - *Acceptance:* The content test (Epic 1) iterates the registries. Adding 'medusa_head' and 'clockwork_knight' requires only def files and art keys. Reordering defs does not break old saves (fixture test).
- **Explicit app state machine and flow modules** — Replace app.ts with an explicit FSM plus flow and service modules, and remove setTimeout-driven transitions.
  - *Implementation:* app/App.ts (boot and wiring, <= 200 lines); app/fsm.ts with states boot/title/menu/classSelect/play/modal/transition/over, enter/exit hooks, and a transition table (illegal transitions throw in dev); app/flows/{menuFlow,runFlow,modalFlow}.ts; app/services/{quality,persistence,mood}.ts. The 240 ms door and 400 ms floor setTimeouts become loop-driven tweens, so a visibility change cannot fire a stale callback. The existing 'this.run === run &&' guard in the hint-hiding timeout shows this hazard is already real.
  - *Acceptance:* app.ts is deleted and App.ts is <= 200 lines. An FSM unit test covers all legal transitions and rejects illegal ones. A Playwright test backgrounds the tab mid-fade and resumes in the correct room.
- **Dev console on the command layer** — An in-game console that issues the same commands as the UI, plus dev-only ones.
  - *Implementation:* src/dev/console.ts is a lazy chunk, loaded only in vite dev or with ?dev=1. It opens with backtick, gamepad Select+L3, or a 3-finger long-press. Commands: spawn knight 3 --elite, boss vlador, card holy_cross 2, item grim_sickle 4, god, gems 999, lvl 12, goto boss|shop|rest, floor 3, seed 7Q2ZP-0, timescale 0.25, killall, hash, replay save, overlay flow|hitbox|spatial. Arguments autocomplete from the registries. Dev commands are recorded in replays with a DEV flag, and such replays are marked 'tainted'.
  - *Acceptance:* The console chunk is absent from the initial path (budget check). 'spawn gargoyle 20' on floor 1 spawns 20 Gargoyles with 0.8 s telegraphs. A replay containing 'god' shows a 'dev-tainted' badge.

**Depends on:** DES (multi-behaviour enemies, status effects, new floors) and META (achievements, codex, bestiary, run stats) consume the bus, column registry and content registries; UI must render RunController 'pending decision' descriptors instead of mutating Player in callbacks; Epic 1 CI and Epic 3 sim-hash parity tests must exist first to guard the refactor
**Risks:** A big-bang refactor causes regressions. Mitigation: land it in slices (bus, then commands, then scheduler, then app split), each with sim-hash parity and Playwright smoke; Event payload design churn as other domains ask for fields. Mitigation: versioned catalog with 3 numeric slots; Profiling wrapper overhead. Mitigation: compiled out unless w.profile is set
**Constraint check:** Pure TypeScript with no new runtime dependencies. The bus and columns are preallocated typed arrays, so the zero-allocation hot loop holds. The frozen system order keeps the 120 Hz sim deterministic. Commands are plain data, so live play, bots and replays share one code path. The dev console is a lazy chunk outside the initial bundle. Nothing here is platform-specific.

**Review notes:**
- *feasibility* (keep, effort XL): Absorb MET-1's bus, STO-1's StoryBus, SOC-1's command bus and BAL-2's controller extraction. Splitting the 871-line app.ts and 1,055-line world.ts behind parity gates is XL.
- *player* (keep, effort XL): App/World split, command layer and registries enable co-op, bots and replays. Absorbs SOC-1's command bus and BAL-2's controller extraction. Sliced delivery is right; it's XL.
- *completeness* (keep, effort XL): Critical path for MET-5, TEC-3, TEC-7 and SOC. About 40 epics edit world.ts and app.ts, so land this first. Realistically XL.

#### TEC-3 · 3. Chronicle of Blood: determinism hardening, replays and local crash reports

*Engineering, performance, platform & tooling · effort L · impact 5/5*

'Any run is reproducible from its seed' should hold for combat, not just maps. That means freezing device-dependent sim inputs, using portable math across browser engines, hashing the world every second, and recording every tick of intent plus every menu decision. Then a death to Count Vlador's blood spiral can be replayed frame by frame on any device. **Player value:** Daily seeds become fair (a budget phone and a 4K desktop face the same waves). Players can watch replays of victories and their last death. After the OS kills the PWA mid-fight, Continue resumes the exact fight. Bug reports reproduce at the exact tick.

- **Per-run sim profile frozen at start** — Fix the cross-device leak through enemyCap.
  - *Implementation:* Add a SimProfile { capTier: 'full'|'mobile'|'daily' } chosen at startRun (ultra/high give 'full' with a 300 cap; medium/low give 'mobile' with 150; daily seeds always use 'daily' with 150). It is stored in RunSave and the replay header and passed to planSpawns. App.applyPreset no longer writes world.enemyCap. Render-side culling stays per preset.
  - *Acceptance:* The same seed planned on 'ultra' and 'high' yields identical waves and hpMul. A thermal step-down mid-run leaves the next room's plan unchanged. Floor-1 hashes of a daily run match between Pixel 7 emulation and desktop.
- **Separate cosmetic RNG and add a determinism lint** — Cosmetic effects must never consume gameplay randomness, and sim code must never call non-deterministic APIs.
  - *Implementation:* Add World.fxRng (STREAM.cosmetic = 7) for hazard embers (world.ts:931/949), burn embers (enemyAi.ts:28) and the dash/ability trails that currently use Math.random (playerCombat.ts:137, :317). tools/lint-determinism.ts uses the TypeScript compiler API to ban Math.random, Date, performance.now and crypto in src/game, src/gen and src/core (freshSeed is allow-annotated). It also bans raw Math.sin/cos/atan2/exp/hypot/pow in sim and gen code, which must use dmath.
  - *Acceptance:* Lint passes on main after the fixes. Injecting Math.random() into enemyAi fails CI with file:line. Doubling burn-ember density leaves the crit and loot hash sequence unchanged.
- **Portable deterministic math (core/dmath.ts)** — Get bit-identical results in V8, JavaScriptCore and SpiderMonkey for sim and generation.
  - *Implementation:* Implement dsin/dcos (range reduction plus a degree-11 minimax polynomial, |err| < 2e-9), datan2 (octant reduction plus polynomial), dexp (Cody-Waite plus polynomial), dpow for xpReq (or a precomputed integer XP table for L1-99), and len(x,y) = Math.sqrt(x*x + y*y), since IEEE sqrt is correctly rounded and faster than V8's Math.hypot. Replace the ~80 call sites in world, enemyAi, playerCombat, stats and gen/poisson. Float32Array storage already rounds deterministically.
  - *Acceptance:* A golden hash table from Node (V8) for 30 seeded 2-minute boss fights (Gorehorn, Colossus, Vlador x 10) matches Playwright Firefox and WebKit exactly. Floor fingerprints match across all 3 engines for 200 seeds. The 150-enemy tick is no slower.
- **World state hash and checkpoints** — A fast, comprehensive hash of sim state, used for tests, replays and desync detection.
  - *Implementation:* World.hash() is an xxHash32-style fold over the live slots of EnemyStore (x, y, hp, state, t, def), ProjectileStore, PickupStore and HazardStore, plus player transform, hp, energy and timers, wave counters, and Rng internal state (add Rng.saveState(out: Uint32Array) and restoreState). It is computed every 120 ticks into replay checkpoints and exposed through the console 'hash' command.
  - *Acceptance:* A vitest determinism suite (3 classes x 20 seeds x 3,600 ticks of scripted intents) yields identical hash sequences across two runs and across the Epic 2 refactor. Each hash costs under 0.05 ms at 150 enemies.
- **Intent quantization and recorder** — Record every tick compactly, and quantize live input the same way so live play and replay are identical.
  - *Implementation:* Quantize at the source: move as int8/127; aim angle as uint16 (2π/65536); aimPoint as absolute uint16 at 1/16 world unit (rooms are <= 1,920 units); a button bitfield (fire, ability, dash, interact, aimAssist, autoAim, hasAimPoint). replay/recorder.ts writes a change-mask byte plus zigzag-varint deltas into a growable Uint8Array (amortized doubling, no per-tick allocation). Epic 2 commands are interleaved as tagged records, with checkpoints every 120 ticks. The header holds build hash, runSeed, attempt, class, daily flag, SimProfile, meta.statBonus snapshot and unlocked packs. Data is compressed with CompressionStream('deflate-raw'), falling back to uncompressed, and stored in IndexedDB 'replays' (last 10 runs plus all victories, 8 MB cap).
  - *Acceptance:* A 25-minute KB+M victory compresses to <= 250 KB. Recording costs under 0.01 ms per tick. A Playwright aim test at 4K shows no visible aim jitter from quantization.
- **Replay theatre and exact mid-fight resume** — Watch, scrub and verify replays, and resume the exact moment a killed PWA left off.
  - *Implementation:* replay/player.ts loads ?replay=<id> or a dropped .ckreplay (base64 text). It drives the same RunController with the recorded intents and commands and verifies checkpoints, showing 'DESYNC at tick 48,211 - Floor 2 Elite (Axe Armor x2)' on mismatch. Speeds: 0.25x, 1x, 4x, 16x (16x renders every 16th tick). Room starts (seeds + PlayerSave) act as keyframes for jumping between rooms. Game-over gets a 'Watch your last death' button. For exact resume, pagehide mid-combat saves the room keyframe plus the intent tail. Continue fast-forwards the tail headless (~10k ticks x ~0.1 ms, about 1 s behind a 'The keep remembers...' fade). If the build hash differs, it falls back to restarting the room.
  - *Acceptance:* A recorded Phantom Blade run that dies to Vlador's blood spiral replays to the same death tick in Chrome, Firefox and Safari. Killing the tab mid elite fight and pressing Continue restores enemy HP and positions, verified by hash.
- **Local crash capture and bug-report sigil (opt-in, no backend)** — Catch errors in the 120 Hz loop and package a reproducible report that never leaves the device unless the player shares it.
  - *Implementation:* platform/crash.ts hooks window.onerror and unhandledrejection, and wraps the loop's update and render in try/catch that freezes the sim and opens a 'The Count's curse struck!' screen. It stores { build, UA, renderer webgl|webgpu|canvas, preset, seed label, room, stack, last 30 s replay tail + room keyframe } in an IndexedDB 'errors' ring of 20. 'Copy bug report' produces a deflate + base64url string (typically under 20 KB) to paste into a GitHub issue form. Settings toggles: 'Keep local crash logs' and 'Include replay', both on by default and both local only.
  - *Acceptance:* Forcing a throw inside the Rune Colossus spiral via a dev command produces a report. Pasting it into ?bugreport= reproduces the exception at the same tick. Nothing is sent over the network (Playwright request interception asserts zero requests).

**Depends on:** Needs TEC Epic 2 command layer and RunController, so menu decisions are recordable; Needs TEC Epic 4 for the IndexedDB 'replays' and 'errors' stores and the DB version upgrade; UI: replay theatre controls, desync banner and crash screen styling; DES: stable attack-pattern ids for death attribution (e.g. 'vlador.bloodSpiral')
**Risks:** Polynomial math changes curve feel slightly. Mitigation: error under 2e-9, plus golden screenshot comparison; Replays are tied to a build hash; old replays need old builds. Mitigation: keep versioned Pages deployments and show 'recorded on build X'; Fast-forward resume is slow on budget Android (~0.4 ms per tick gives about 4 s). Mitigation: cap the tail at 60 s, otherwise restart the room; CompressionStream is missing on older Safari. Mitigation: store uncompressed
**Constraint check:** This strengthens the determinism rule (runSeed + floorIndex + attemptCounter now also pins combat). Separate PRNG streams are kept and a cosmetic stream is added. Recording writes into a preallocated, amortized buffer, so the hot loop stays allocation-free at under 0.01 ms per tick. Storage is local IndexedDB with no backend. dmath is about 2 KB gz. Works the same on every platform and input method because Intent is device-agnostic.

**Review notes:**
- *feasibility* (keep, effort XL): Absorb SOC-1. Freezing a per-run sim profile isn't enough: enemyCap and the view rect depend on the device, so make them ruleset constants. dmath in generation reshapes Poisson seeds.
- *player* (revise): Replays and crash capture help balance and bug reports. Absorbs SOC-1. Cross-engine dmath only matters for verified boards (cut), so defer it.
- *completeness* (keep): Canonical determinism and replay epic; absorb SOC-1 (same tape, dmath, hashes, ABI). Replays need archived builds, which no release-management epic provides.

#### SOC-1 · Chronicle Core: deterministic command tape and ranked integrity

*Social, multiplayer & community · effort L · impact 5/5*

Turn the README's promise ('any run is reproducible from its seed') into 'any run is reproducible from its seed plus a small tape'. Every Shadow Step, every Holy Cross pick and every gem spent at the lantern merchant becomes a tick-stamped record. Ghosts, leaderboards, co-op, death cams and bug reports all build on it. **Player value:** Players never see this directly, but it makes runs comparable and impossible to fake. A Daily Moon on an iPhone at 'low' becomes exactly the same castle, enemy waves and card offers as on a 4K desktop at 'ultra'. Quitting mid-Count Vlador no longer resets the fight.

- **Command bus: menus emit commands, not mutations** — Move every out-of-tick state change into a typed command applied at a recorded tick. Commands: PickCard{offerIdx}, AllocStat{attr}, ShopBuy{entryIdx}, ForgeUpgrade{slot}, EquipItem, SalvageItem, EventChoice{idx}, ShrineOffer, ShrineLeave, Rest, ChooseExit (implicit via sim), Descend, Abandon.
  - *Implementation:* Add src/game/commands.ts with a discriminated `Cmd` union and a pure `applyCommand(ctx: {run, player, world, meta-rules}, cmd)`. Move the logic out of the app.ts closures into it: onInteract shop/forge/campfire/shrine/altar, applyEvent, offerItem, openLevelUp, cardChoice. Add `Run.tick: number` (u32), incremented in App.update. Screens in ui/screens.ts receive an `emit(cmd)` callback instead of mutating Player. App's modal flow stays the same, but every handler becomes `this.exec(cmd)`, which also appends to the tape. Offer lists (offerCards and shopStock outputs) are recomputed deterministically during playback, so a command stores only indices.
  - *Acceptance:* A grep test fails if app.ts or screens.ts contains `.scrap -=`, `.addCard(`, `.attrs[` or `item.level++`. A headless vitest drives all 5 mystery events, shop, forge, shrine and campfire purely through applyCommand and asserts the resulting PlayerSave. Live gameplay behaviour is unchanged: the existing sim tests and a 3-floor scripted bot run produce identical end stats before and after the refactor.
- **Quantized intent tape with zero-alloc recording** — Record each sim tick's Intent and quantize it before it reaches `World.update`, so live play and playback see bit-identical inputs.
  - *Implementation:* Add src/replay/tape.ts with `quantizeIntent(intent, player)`. moveX/moveY become int8 (×127). The aim direction becomes u16 (angle / 2π × 65536). The mouse aimPoint is stored relative to the player as int16 at ½-unit precision, then rebuilt as `p.x + dx*0.5` using only exact arithmetic. One flag byte holds fire, ability, dash, interact, aimAssist, autoAim and hasAimPoint. TapeWriter appends into a preallocated 64 KB Uint8Array ring: a run-length varint for identical ticks, zigzag deltas otherwise, and commands interleaved as escape records. It flushes on room transitions to IndexedDB (`tape:<runId>:<chunk>`) through CompressionStream('deflate-raw'), which is native and costs no bundle; without it, chunks are stored raw. App.update calls `tape.record(intent)` right after `input.sample`.
  - *Acceptance:* Recording adds ≤ 0.01 ms per tick and makes zero heap allocations inside the tick (checked by a vitest that counts allocations via a Proxy-free bench harness). A 30-minute KB+M run deflates to ≤ 300 KB and a gamepad or touch run to ≤ 150 KB, measured on 3 recorded human runs. Playing a tape back through the real World reproduces kills, damageDealt, scrap and IGT exactly.
- **Room-entry keyframes and an exact PlayerSnapshot** — `World.loadRoom` rebuilds every pool from the room seed, so the only state carried between rooms is Player plus Run. A complete snapshot at room entry gives instant seeking, honest resumes and replay segments.
  - *Implementation:* Add `PlayerSnapshot` to src/game/player.ts. It holds every field, including abilityCd, dashCd, energy, exact hp, crossT, axeT, waterT, requiemT, orbitAngle, regenAcc, trailAcc, guaranteedCrit, metaAttrs (including curse deltas), cards and equipment. Add `Player.snapshot()` and `Player.restore()`. Run gains `keyframes: {tick, floor, nodeId, visited, elapsed, player: PlayerSnapshot}[]`, captured in App.enterRoom. RunSave moves to v2 with `entry: PlayerSnapshot` plus the current PlayerSave, with a migration from v1 in save/db load.
  - *Acceptance:* Restoring any keyframe and simulating the rest of the tape gives the same final state hash as playing from tick 0. A snapshot is ≤ 3 KB of JSON. v1 saves still load as 'Continue Run'.
- **RNG stream hygiene and a determinism lint** — Separate the gameplay RNG from the cosmetic RNG so particle tweaks never change who crits, and catch nondeterministic calls in tests.
  - *Implementation:* Extend STREAM in core/rng.ts with combat: 7, ai: 8, fx: 9. World gets `rng` (combat: crit, ±8% variance, drops), `aiRng` (enemy timers, boss pattern choice, rockfall offsets) and `fxRng` (ember and smoke gating; never read by state). Replace `Math.random()` at playerCombat.ts:137 and :317 with `w.fxRng`. Add tests/determinism.test.ts, which scans src/game and src/gen and fails on Math.random, Date.now, performance.now or `new Date`. The existing sim smoke test is extended to hash state after a scripted 3-room run.
  - *Acceptance:* The lint test fails when Math.random is added to src/game. Changing the ember particle rate in enemyAi.ts leaves the 3-room state hash unchanged. Two runs of the same tape in the same process give identical hashes.
- **dmath: cross-engine deterministic transcendentals** — Replace the engine-defined Math.sin/cos/atan2/pow/exp inside the simulation with pure-arithmetic versions. +, −, ×, ÷ and sqrt are correctly rounded IEEE in every engine, and JS forbids FMA contraction.
  - *Implementation:* Add src/core/dmath.ts with `dsin`/`dcos` (Cody-Waite range reduction plus degree-11/10 minimax polynomials), `datan2` (octant reduction plus a degree-9 polynomial), `dhypot = Math.sqrt(x*x+y*y)`, and `dexp`/`dpow` only where the sim needs them (stats curves are precomputed tables). Swap them in world.ts, enemyAi.ts, playerCombat.ts and stats.ts (xpReq uses `Math.pow(L, 1.45)`, which becomes a 200-entry integer table built with dpow). The render and audio layers keep native Math.
  - *Acceptance:* A golden tape (2 minutes of the Floor 2 Rune Colossus fight) produces the same state-hash sequence in Node/V8, Chromium, Firefox and WebKit via a Playwright CI matrix. dsin is within 2 ulp of Math.sin over 1e6 samples. The sim perf test stays within +5% of the current ~0.3 ms per 140-enemy tick.
