# Appendix A — Current-state gaps by area

[← Roadmap overview](../ROADMAP.md)


### Enemies, elites & bosses

- Each enemy gets exactly one AI from a monolithic `switch (d.ai)` in src/game/enemyAi.ts, which has 6 modes: chase, flutter, ranged, caster, charger and boss. Skeleton and Ghoul share the same 'chase' brain and differ only in stats. No enemy has a second attack, and melee chasers have no attack at all. Their damage is pure body contact (the contact check calling world.hurtPlayer), so close-range hits feel unavoidable and untelegraphed.
- Behaviour and presentation are keyed by string compares on d.key. fireRanged branches on 'archer' and 'witch', the charge wall-stagger excludes 'count', and rockfall is hard-wired to 'ogre'. world.hitEnemy and killEnemy pick bone or blood particles via `bony = d.key === 'skeleton' || ...`. renderer.makeEnemyView and syncEnemies special-case bat, ogre, golem and count and rely on a hand-maintained ENEMY_HEIGHT table. Adding one monster means editing 5+ files.
- EnemyStore has one overloaded scratch set: state (Uint8), t, aux, fireT and dirX/dirY. Each boss hand-numbers states 0–7 with different meanings. There is no per-move cooldown storage, no affix or flags column, no parent link for multi-part bodies, no awareness or aggro state and no hop height. Status effects stop at burn, stun and knockback. def is a Uint8Array, so the game caps at 256 defs, boss parts included.
- Elites are only multipliers: ELITE = hp×3, dmg×1.4, size×1.3, xp and scrap ×3, plus speed ×1.08 in spawnEnemy. Archer, Witch and Gargoyle also get extra arrows or fireballs. The only tell is a gold aura ellipse. Elites have no affixes, no names and no behaviour changes, and planSpawns simply excludes bats from the elite pick.
- Telegraphs come in circles only: HAZ.TELEGRAPH (a circle that detonates) and HAZ.SHOCK (an expanding ring). There are no line, lane, cone, donut, tracking or beam telegraphs. POOLS.hazards = 64 is shared by player holy fire, moon trails, wave SPAWN rings and Colossus spike volleys. The generic windup tell is an orange flash on `state === 1` in renderer.syncEnemies, which boss moves in states 4–7 (all Colossus and Vlador attacks) never trigger.
- Enemy projectiles can only fly straight or home (PF_HOMING, 1.1 rad/s turn). ProjectileStore.flags is a Uint8 with 6 bits already used, and no flag exists for sine-weave, accelerating, curving, delayed, splitting, bouncing or owner-orbiting bullets. Enemy shots cannot be cancelled or parried. Boss patterns are hand-rolled loops around a local radial() helper with no safe-gap guarantees.
- Spawning draws from one global table filtered by minFloor with flat weights, so the Moonlit Throne still mostly rolls Skeletons (weight 34) and Blood Bats (26). FLOOR_THEMES biomes never shape rosters, and there are no squads or formations. Every enemy knows the player's position from tick one: there is no idle, dormant or alert state. Waves trigger only on alive ≤ 2 or after 14 s, and mobile cap folding just multiplies everyone's HP.
- Bosses are fixed per floor via BOSS_FOR_FLOOR[min(floor, 2)]. The only 'phase' is a single `hpFrac < 0.4` enrage flag: +30% speed and denser bullets. Each boss has about 4 moves chosen by a flat random roll. The intro is a HUD banner plus a 1.6 s idle timer, with no transitions, invulnerability windows, multi-part bodies, arena changes or bespoke deaths (killEnemy just wipes the room and draws rings). Every boss shares one 'boss' music style, and there is no mini-boss tier, boss rush or bestiary.
- Testing and determinism have gaps. tests/sim.test.ts only checks that each boss survives 40 s at 1% player damage, with no per-move coverage and no golden replay hashes. Cosmetic rolls such as burn embers (`w.rng.next() < dt * 10`) and charge smoke draw from the simulation RNG, so any FX tweak changes combat outcomes for the same seed.
- The enemy presentation path allocates and has no rig. syncEnemies destroys and rebuilds an EnemyView whenever a pooled slot changes def. Monsters animate only by whole-body transforms (bob, squash, white flash, club and wing rotation), so a windup pose cannot read differently from an attack pose.

### Biomes, run structure & world

- The floor index stands in for the biome, the difficulty and the boss choice at once. `CONFIG.floors = 3`, `CONFIG.floorDifficulty = [1, 1.55, 2.2]`, `BOSS_FOR_FLOOR[Math.min(floor, 2)]` (src/gen/spawner.ts), `FLOOR_THEMES[Math.min(w.floor, ...)]` (src/render/renderer.ts) and `KEY_ROOT[floor % 3]` (src/audio/music.ts) all index by floor. A 4th floor would quietly reuse the Moonlit Throne's palette, Count Vlador and Throne difficulty.
- Biomes differ only in colour. `FloorTheme` holds 14 colours, and `generateRoom` uses the same global CONFIG settings (BSP leaf size and depth, cavern fraction, fill and passes, corridor width) on every floor. The only biome-specific logic is hardcoded: `floorIndex === 1` picks skulls and coffins over puddles in `decorate()` (src/gen/room.ts), and `RoomView.drawFloor` checks the string `th.name === 'Moonlit Throne'` to draw a marble checkerboard.
- The run is a fixed line of floors. `App.nextFloor()` calls `run.enterFloor(run.floor + 1)`, and the boss room spawns a single 'portal' interactable. There are no acts, no biome forks and no route choice; branching exists only inside one floor graph. `RunSave` (version 1) stores only a `floor` number, so any route or biome data needs a save migration.
- Tiles can only be WALL, FLOOR, DOOR or SEALED (src/gen/grid.ts). There is no terrain layer: no water, pits, acid, low walls or breakable walls. `World.updateFlow` is a unit-cost BFS over `TILE_FLOOR` only. Every `HAZ` kind in src/game/stores.ts is a combat effect (HOLYFIRE, WELL, TELEGRAPH, SPAWN, TRAIL, SHOCK), and `POOLS.hazards` is 64. Rooms contain no environmental hazards at all.
- Every room has the same shape. All rooms run west to east: `placeDoor` only knows 'W' and 'E', and `World.checkExit` only tests `p.x >= (w-1)*T`. Sizes are fixed per kind (combat 60x40, small 34x24, boss 46x34). All three bosses fight in the same octagon with 4 pillars. There is no prefab or template system, and shop, rest and event rooms are a 12x8 hub carved into BSP noise.
- There are no secrets and only one ending. `mapView` draws every node, and nothing is hidden, breakable or locked behind a key. The final-floor portal always calls `endRun(true)`. `MetaSave` tracks only souls, classes, packs, statBonus, runs, wins, bestFloor and the last 20 seeds; it has no endings, discoveries or completion data.
- There is no choice of run length and no endless mode. The main menu offers New, Daily and Seed. Graph columns are fixed at 5-7. The HUD label is `Floor N · Kind r/n`, and the end screen prints `Floor reached x / CONFIG.floors`. Nothing echoes the reference screenshot's 'Round 3/30' pill.
- Scaling is linear and tuned for exactly 3 floors: `floorHpMul = 1 + 0.55·floor`, `floorDmgMul = 1 + 0.32·floor`, XP `×(1 + 0.25·floor)` in world.ts, loot piles `int(2,4) + floor` with `+floor·2` gems each (loot.ts), shop prices `1 + 0.25·floor` (economy.ts), and elites hardcoded to `floor >= 1`. Longer or endless runs need one depth curve that keeps going and tapers.
- Content tables are global rather than per biome. The spawner uses `ENEMY_DEFS.filter(d => d.minFloor <= floor)`, `CONFIG.nodeWeights` is a single table for every floor, `pickEvent` draws evenly from 5 global EVENTS, and loot has no biome bias. Biomes cannot have their own roster, map mix or rewards.
- The world has very little presentation. The map is a flat 800x300 SVG of circles for the current floor only, with no castle overview and no route history. A floor intro is a 2.5 s `hud.banner(name, subtitle)`, and every room and floor transition uses the same black CSS fade (240 ms or 400 ms).

### Procedural generation technology

- Room layout ignores room kind and has no archetypes. generateRoom() in src/gen/room.ts runs the same recipe for every non-boss room: BSP (minLeaf 8, depth 6), 30% cavern leaves, then A* corridors. Start, event, shop and rest rooms differ only by a hard-coded 12x8 central hub; measured in a scratch run, event, shop and rest produce byte-identical tiles for a given seed. All three bosses share one hard-coded octagon with 2x2 pillars at fixed 0.33/0.67 fractions. There are no prefabs, set-pieces, landmarks or themed zones.
- The tile vocabulary is only 4 codes in one Uint8Array (WALL/FLOOR/DOOR/SEALED in src/gen/grid.ts). isPassable, World.solidTile/los/updateFlow, the minimap and RoomView all hard-code those values. Nothing can represent pits, low walls that projectiles pass over, breakable walls, vault gates, trap plates or raised ground. Carpet is a separate ad-hoc Uint8Array, and pillars are WALL tiles with a cosmetic decor overlay.
- Decoration is cosmetic only and follows no rules. decorate() rolls a chance per tile: torches at least 5 apart at 55%, windows 7%, banners 5%, chains 3%, bones 2.5%, candelabra 0.6%. It only branches on floorIndex. There is no door-flanking, no symmetry and no zone set-dressing. A combat room averages about 94 decor items, but none of them (candelabra, coffin and so on) can be hit, broken or looted, so the Castlevania candle loop is missing.
- Every layout pass shares one RNG. BSP, caverns, corridors, spawn pick, pillars and decor all draw from a single Rng(hashCombine(seed, STREAM.layout)) in sequence, so inserting any new pass (traps, secrets) reshapes every map after it and silently breaks shared and daily seeds. There is no GEN_VERSION. tests/gen.test.ts only compares a fingerprint of the first 3 rooms against itself within the same build, with no golden snapshots across commits. poissonDisc() uses Math.cos/Math.sin, which are not bit-identical across JS engines, so spawn and loot positions for a daily seed can differ between Safari and Chrome.
- Spawn fairness is checked by straight-line distance only, and only at generation time. Enemies are kept 6 tiles (euclidean) from spawn, but path distance and line of sight are never checked. Measured over 1,080 combat/elite rooms: the nearest wave-1 enemy can be 6 BFS tiles away; 9.8% of rooms have a wave-1 enemy within 8 tiles; 4.3% put a Bone Archer, Hex Witch or Gargoyle within 12 tiles with clear line of sight to the spawn tile. Wave 2-3 points are fixed at generation, and World.startWave() never checks them against the player's current position, so a 0.8 s spawn telegraph can open under the player's feet.
- There are no quality metrics or budgets. Nothing measures floor ratio (43% in combat rooms), open-arena size, loops, dead ends, cover density or pacing. Spawn-to-exit BFS distance in combat rooms ranges from 46 to 119 tiles, a 2.6x spread. Generation cost is untested: measured at 2.2 ms average and 13.7 ms worst per combat room in Node. astar() allocates four w*h typed arrays per call, and validateConnectivity() can relabel the whole grid up to 64 times.
- Rooms keep no state. Run.roomFor() regenerates rooms from the seed, and RunSave v1 stores only nodeId, visited and a single roomCleared boolean. World copies tiles, but RoomView bakes room.tiles into one static GraphicsContext and HUD.buildMinimap draws a canvas once. A runtime map change (broken wall, opened vault, smashed candles) can't be redrawn incrementally or survive Continue Run.
- Door layout is fixed. The entrance is always a sealed door on the west edge at spawn.y, and exits are always on the east edge at (i+1)*h/(n+1). DoorInfo.side is only 'W' | 'E', and World.checkExit() just tests x >= (w-1)*T. There are no north/south doors, no internal gates or portcullises, and no section-by-section progression, even though a 60x40 combat room is already about 2.5 by 3 screens.
- Nothing in a floor is optional or hidden. The graph has 7 node types (about 11.9 nodes per floor: combat 46.7%, rest 14.5%, shop 9.8%, event 6.8%, elite 5.4%). There are no secret, vault, challenge or puzzle nodes and no keys or locks. Loot comes only from rollRoomLoot() on clear and from enemy kills, so exploring a room is never rewarded.
- The spawner ignores room geometry. planSpawns() fills Poisson points across the whole room with a 1-tile clearance check. Bone Archers don't look for ledges or cover, Axe Armors (chargers) don't get charge lanes, Blood Bats don't roost and Ghouls don't rise from coffins, so encounters never use the room's shape.

### Combat systems & buildcraft

- Monolithic damage path. World.hitEnemy(i, amount, critMode, procs, kx, ky, kb) (src/game/world.ts:456) is the only damage entry point. It has no damage type, no source id and no resistance step. Card procs (lifesteal, burn, singularity pull, chain) are hard-coded inside it, and particle style is picked by string-comparing d.key ('skeleton', 'archer', ...). Burn damage-over-time skips it entirely: enemyAi.ts:24-33 subtracts hp directly, so burn ticks show no numbers, are not tracked per source and skip any on-hit logic.
- Only one real status exists. Burn is two Float32 arrays (EnemyStore.burnDps/burnT) combined with Math.max, so the 'per stack' in Burning Hex means copies of the card, not stacks on the enemy. Stun is only used by Shockwave Dash and by charging into a wall (bosses are excluded). There is no freeze, shock, poison, bleed or curse, and no reactions between statuses.
- The hook system is closed. Behaviour cards are a fixed HookKey union (cards.ts:9), mirrored in zeroHooks() (player.ts:10) and read through p.hooks.* in playerCombat.ts, world.ts (lines 468-493, 766, 887, 897) and renderer.ts:477. One new behaviour card touches four or more files. Stacking is linear and uncapped: fork spawns 2×stacks shards per hit, and cross/axe fire rate scales 1+0.25(n−1). Meanwhile extra singularity stacks add only the +15% crit-damage mod, because the pull is a boolean check. CardDef.tier is display-only.
- There are no Castlevania-style sub-weapons. Holy Cross, Executioner's Axe, Holy Water and Requiem are passive auto-fire timers inside updateSubWeapons(). There is no sub-weapon slot and no input for one (Intent has only fire/ability/dash/interact). PICK.HEART is a 15% heal, so the series' hearts-as-ammo economy is missing.
- Weapons don't change how you fight. basicAttack() branches on the class's fixed attack.kind ('slash'|'orb'|'dagger'), and all 7 weapon items (equipment.ts:28-34) are stat sticks; Grim Sickle, for example, is just +11 dmg and +5% crit. There are no weapon families, attack patterns, elements, affixes, charge attacks or weapon swapping.
- Defence has no timing skill. Dash just grants i-frames: hurtPlayer() returns early while dashT>0, and the projectile check at world.ts:865 skips the call altogether, so a frame-perfect dodge counts the same as a panicked one. S_WINDUP states exist in enemyAi.ts, but nothing lets the player interrupt them. There is no projectile deflect, combo meter or hit-stop.
- The crit and proc rules have quirks. Shadow Step's guaranteedCrit is spent on the first critMode-0 hit, which can be a wisp tick (orbitHits passes critMode 0 for familiars) or a Requiem nova. Familiar ticks also trigger burn, chain and lifesteal at full rate. Storm Chain is a flat 20% per hit with no proc coefficient, so twin daggers (2+ projectiles every 0.26 s) trigger it several times more often than Arc Slash.
- Combat randomness shares w.rng with enemy AI, spawning and even burn particle jitter (enemyAi.ts:28). Taking Keen Edge changes crit rolls, which shifts every later AI decision in the room. playerCombat.ts:137 and :317 call Math.random() inside the simulation module. Runs still replay from the seed plus identical inputs, but you cannot A/B-test two builds against the same enemy behaviour.
- Run modifiers are ad hoc and buggy. The Forgotten Armory curse lowers p.metaAttrs.vit (app.ts:821), but PlayerSave does not store metaAttrs and Player.fromSave rebuilds them from meta, so the −10 max HP curse vanishes on Continue Run. There are no relics, curses, blessings or items with drawbacks, and the luck parameter of rollRarity() is never driven by run state.
- Build identity is thin. 27 cards across 7 tags: FLAME has only 2 cards and there is no FROST, POISON or SUMMON at all. Offers can't be rerolled, banished or skipped, and maxed cards stay in the pool. tagCounts is computed in Player.recompute but only ORBIT is used. There are no evolutions, no per-source damage breakdown (only p.damageDealt), no autonomous summons (orbitals are just hit circles), and EnemyDef has no resistance or material fields.

### Classes, characters & companions

- Class behaviour is hard-wired by id. playerCombat.updatePlayer branches on `p.cls.id === 'vanguard' / 'weaver' / else` for the ability, basicAttack switches on the closed `AttackKind = 'slash'|'orb'|'dagger'`, and renderer.syncPlayerClass() and renderer.portrait() special-case `cls === 'weaver'` for the rune ring. statPanel's auto-assign `pref` map (screens.ts), hud.ts ABILITY_ICON and meta.ts CLASS_COST are all keyed by the closed `ClassId` union. Adding one hunter touches about 9 files, and each new mechanic adds another if-branch.
- Each class has one edge-triggered ability. Intent has a single `ability` latch (Space/RMB, pad A, one touch button). There is no second ability, no ultimate, and no hold, charge or channel input (a shield guard or a charged whip needs one). Gamepad Y/LB/LT and keyboard Q/R are unused in play. Ability tuning is hard-coded in combat code instead of ClassDef/CONFIG: SHOCK_DASH {0.26 s, 240 u}, Singularity radius 160 and damage 80+3×base, Shadow Step range 260.
- Class-specific state is bolted onto Player as one-off fields: `abilityDashT` (Vanguard), `guaranteedCrit` (Phantom), plus crossT/axeT/waterT/requiemT for card hooks. There is no per-class state block, and PlayerSave has no field for loadout, talents, pet or skin.
- Builds don't depend on class. All 27 CARDS are class-agnostic: offerCards filters only by pack and rarity, and only Split Volley's text mentions a class. The only class-specific progression is the stat auto-assign order, so Vanguard, Weaver and Phantom runs drift toward the same card and item builds.
- There is no per-class meta progression. MetaSave v1 holds `classes: ClassId[]`, a global `statBonus` and a 20-entry history that records `cls` but is never aggregated. There is no mastery, no per-class records, no feats and no reward track. app.ts loads meta with a shallow spread `{...defaultMeta(), ...saved}`, so nested per-class data would need a real migration.
- Familiars are anonymous stat counters. `stats.orbitals` spawns N identical hit-circles at a fixed radius of 58 (orbitHits: 0.3 s per-enemy cooldown, dmg = orbitDmg + 0.3×base). They all draw with the single `shapes.imp` context, so the Bat Familiar card and the Bat Charm item render as imps. Pets have no entity, AI, name, level or persistence. enemyAi aims at `w.player` (p.x/p.y) everywhere, so allies can never draw aggro.
- Hero colours can't be swapped. drawVanguard, drawWeaver and drawPhantom embed about 40 hex literals in Pen calls (0xc8283c plate, 0x7a3cc8 robe, 0x1f5068 cloak). ShapeCache.heroes is `Record<ClassId, …>` with no variant key. All heroes share one weapon pivot (8, −19) and animate only through bodyWrap transforms (bob, squash, ±0.04 rad tilt).
- Class select is just a stat sheet: six numbers, a blurb and the ability name (screens.classSelect). It has no playstyle preview, difficulty rating, loadout, skin or pet choice. Locked classes are gated only by souls (60/90), never by something done in a run.
- New mechanics could break determinism. All combat randomness (crit rolls, ±8% damage variance, Storm Chain procs) draws from one per-room `w.rng`, so any new class or pet proc that uses it shifts every later crit roll in the room. There is no STREAM for kits or companions. Sim code already calls Math.random() for particle emission (dash trail and shockwave sweep in playerCombat.ts). That is harmless today, but new kit code could easily copy the pattern into gameplay decisions.
- Tests only smoke-test classes. sim.test.ts loops CLASS_ORDER with every card for 4 rooms and asserts kills > 0. There are no per-ability unit tests, no class-vs-class clear-time or damage-taken harness, and no replay or state hash, so balancing 9 classes would be guesswork.

### Meta-progression, economy & hub

- Saves have a version field but nothing ever migrates them. MetaSave, RunSave and Settings all carry a literal `version: 1`, and App.boot merges a stored save with a shallow spread ({...defaultMeta(), ...saved}). As a result: a new nested key (for example a 6th attribute in statBonus) comes through as undefined or NaN; a removed card or item id crashes later lookups (pauseScreen reads CARD_BY_ID[id].rarity); and there is no checksum, no backup, no export/import and no navigator.storage.persist(). iOS Safari can evict the whole 'crimson-keep' IndexedDB store after 7 days without use.
- Gems do two jobs. 'scrap' in code and 'gems' in the UI is spent in the run at the merchant and forge, and is also converted at run end by soulsFromRun = floor(scrap*0.5) + floor*10 + 60. Every potion or forge level therefore cuts meta income. From loot.ts and the boss purses, a full run yields roughly 560 gems: a victory that hoards everything pays about 360 souls, while one that spends at shops and the forge pays about 80, so hoarding is worth about 4.5x. The floor bonus uses the 0-based floor, so dying on Floor 1 gives a floor bonus of 0.
- Save-scum exploits on Continue. World.loadRoom re-creates the campfire, anvil, altar and merchant with used=false, and App.shopCache lives only in memory. After pagehide→saveRun and a Continue, the same event altar is fresh again. The Wandering Ghost's +2 stat points, the Moonlit Fountain's Vital Draught card and the Blood Altar's rare card can be farmed without limit. A won Fortune-Skull gamble wins again too, because cardRng(91) hashes level and card count, not gems. Campfire heals re-arm and sold-out shop stock comes back. In the other direction, unopened chests and uncollected gem piles in a cleared room vanish on Continue, because onCleared() is not replayed.
- Boss purse bug and loose economy plumbing. World.killEnemy gates gem drops with rng.next() < (elite ? 1 : 0.3), and bosses are not elite. Gorehorn, the Rune Colossus and Count Vlador therefore drop their 60/90/140 gems only 30% of the time, so the biggest single gem source in a run is a weighted coin flip. Abandoning pays the same souls as dying, and the 'abandoned' result type is never written. Pack prices are hard-coded a second time in app.ts showUnlocks ({holy:90, blood:90, reaper:160}) instead of reading PACKS[k].cost.
- The only meta sink is a flat 10-row DOM shop: 2 classes (150 souls), 3 packs (340) and 25 stat ranks (5 attributes × 30..130 = 2,000), for 2,490 souls in total. There are no prerequisites, branches, utility perks or respec, and souls have no use once it is bought out. Nothing in the world frames it either: App's states are boot/title/menu/play/modal/over/transition, and meta is reached through mainMenu → unlocksScreen.
- Difficulty stops at the fixed 3-floor curve (CONFIG.floorDifficulty [1, 1.55, 2.2], floorHpMul 1+0.55f, floorDmgMul 1+0.32f). After the first victory there is no ascension or heat, no modifiers, no extra reward and no record of what difficulty a run was played at.
- Daily Moon is just hashString('daily:' + UTC date). The date key is not zero-padded. The class is free to choose, the end screen allows unlimited attempt+1 retries, and there are no mutators, score, streak or calendar. SeedRecord does not even store that the run was a daily, and there is no weekly challenge.
- Runs record almost nothing. Player only counts kills, damageDealt and roomsCleared. There is no kills-by-enemy array and no hits-taken counter. Killer attribution is missing: hurtPlayer gets an attacker index only for contact hits (enemyAi.ts:212), and every projectile or hazard hit passes -1 because ProjectileStore has no source-def column. Bestiary, achievements, death recaps and statistics cannot be built from this. recordRun writes meta.history (20 SeedRecords of seed/attempt/cls/result/floor/date) and meta.bestFloor, but no screen reads either.
- There is no codex, bestiary, achievements, run-history screen or cosmetics. Heroes are tied to shapes.heroes[cls] and renderer.portrait(cls) with one palette each, so once the 2,490 souls are spent there are no long-term collection goals. Meta writes are also blind: app.ts writes 'meta' to IndexedDB on every 'cleared' event even though meta never changes during a run.

### Art, animation, VFX & lighting

- Characters are monolithic GraphicsContexts (drawVanguard, drawSkeleton, drawOgre and the rest in src/render/art/characters.ts). All animation is transforms on bodyWrap in GameRenderer.syncPlayer/syncEnemies: bob of 2.5 px or less, squash of about 3%, rotation of 0.04 rad. Legs and arms never move (Skeleton legs are static strokes). The only separate parts are the bat wings (scaleY flap), the Gorehorn club (rotation), and the golem runes and cracks (alpha). E.phase is plain time rather than distance travelled, so any leg cycle built on it would foot-skate.
- There are no facial expressions. Eyes are baked into the body context through Pen.eye/glowEye with a fixed 'look' offset (0.2-0.6), so heroes and monsters never blink, never track the player and never change mood. Gorehorn's two heads are one static drawing.
- Deaths are not animated. World.killEnemy releases the slot right away and syncEnemies hides the view the same frame, leaving only smoke, blood or debris bursts. The player's death is a 1.4 rad tilt plus an alpha fade. Nothing persists: no corpses, bone piles or blood decals.
- There is no hit-stop or impact framing. hitEnemy only sets E.flash = 0.12 (white silhouette fade). loop.timeScale is used only for player death (0.35) and boss defeat (0.3). A crit differs from a normal hit only by particle count and yellow text, and damage text calls String(dmg) on every hit.
- Telegraphs use one visual for everything: hazardCtx.tele, an orange-red circle with a 0.18-alpha growing fill, for every AoE, from the Gorehorn slam (r=135) to Colossus spikes (r=48). Charges (Axe Armor, Gorehorn) and aimed fans (Colossus 7-shot fan, Vlador hellfire) get no ground shape, only the enemy silhouette strobing orange at 30 Hz. Spawn rings strobe at 25 Hz and the invuln blink runs at 20 Hz, a photosensitivity risk. Red telegraphs and the Count's 0xff2244 blood bullets sit on red carpet (0x9a1630).
- The palette is not semantic. Render code holds about 230 hex literals (renderer 35, characters 116, props 63, roomView 18), and the sim emits about 51 raw colors through FxSink (world.ts, enemyAi.ts, playerCombat.ts), so colorblind palettes cannot ship. Chest rarity is told apart by hue alone. The only accessibility visual setting is the screen-shake toggle. FloorTheme.ambient and FloorTheme.accent are defined but never read.
- Lighting is additive only. RoomView.lights glow sprites and the GlowBatch halos sit on top of a fully lit world: no darkness, no falloff on floors, and colored light never tints surfaces. The vignette is a static 256x256 canvas gradient whose tint is reset to white on room entry. Moonbeams are 0.09-alpha polygons.
- The environment is static and flat. Outside the walls is a flat theme.void fill. Windows are fixed vector glass with no vista. There is no weather. Decor is baked into one decorCtx, so banners, chains and cobwebs cannot move; only flame scale flicker and door badges animate. The three floors differ by 14 colors, plus a marble checker for Moonlit Throne and skulls versus bones.
- Presentation flow is thin. Every door and floor change is a DOM div opacity fade (.22 s) with a setTimeout of 240 or 400 ms. A boss arrives as a DOM HUD banner plus boss_roar, with no camera work, no world-space title card and no beat at enrage (40% HP) apart from the golem crack overlay.
- Art performance and tooling: RoomView draws the floor, walls and decor as a few huge GraphicsContexts, with thousands of per-tile rects, bevel lines and mortar strokes in a 60x40 room, re-rendered every frame at up to a 4K backbuffer. Each enemy is a Container of 5-7 Graphics, and makeEnemyView destroys and recreates it when a slot changes def. Outline width is a fixed 3 world units, roughly 1.8 px on phones and 5 px at 4K. The Canvas2D fallback re-rasterizes every vector each frame. Render-side randomness uses Math.random (burst, shake, lightning, flicker phases), so screenshots cannot be reproduced. There is no shape viewer and no art tests: ?debug=1 only exposes window.__ck.

### Music & sound

- Music is one 142-line arpeggiator (src/audio/music.ts) with 5 hard-coded STYLES. The three floors differ only by the KEY_ROOT transposition (D/E/C). Gorehorn, the Rune Colossus and Count Vlador all share one 'boss' style (152 bpm, i-bII-i-V), so there are no biome themes, no leitmotifs and no per-boss identity.
- The music does not adapt. App.setMoodForRoom picks a mood once per room, so 'battle' sounds the same with 1 Skeleton or 140 enemies, at low HP, with an elite present, or with a boss at 10%. Music.setMood hard-cuts (step=0, nextTime=now+0.12) with no crossfade or bar quantization, and every return to 'explore' restarts at bar 1. Pause, death slow-mo (timeScale 0.35) and boss-defeat slow-mo (0.3) leave the music untouched.
- Synthesis uses bare oscillators. The 'harpsichord' is a square wave into a 2600 Hz lowpass, the 'organ' is a triangle pad, the bass is a sawtooth, the kick is a sine sweep and the hats are Math.random noise. There is no FM, detune/chorus, stereo image or reverb, and every note creates 3 Web Audio nodes (Osc+Biquad+Gain).
- The scheduler runs inside App.render: Music.tick() has a 0.25 s lookahead, so rAF hitches starve it, and the 'nextTime < currentTime - 0.5' reset causes audible skips. Composition and Web Audio are fused in playStep, so nothing about the music can be unit-tested in vitest's node environment.
- The SFX vocabulary is 20 names (the SfxName union in src/game/fx.ts), and most are reused. Holy Cross plays 'shoot_dagger', Executioner's Axe plays 'shoot_slash' and Requiem plays 'explosion'. Holy Water is silent. Axe Armor's charge reuses the player 'dash'. All 7 enemies share 'hit'/'enemy_death', and every boss attack is 'boss_roar' or 'enemy_shot'. HAZ.TELEGRAPH (ogre slam 0.85 s, golem spikes 0.95 s) and HAZ.SPAWN wave warnings (0.8 s) make no sound. There are no footsteps, ambience, UI focus/back/deny sounds or low-HP cue.
- The mixer is first-come-first-served. Audio.play returns early once 8 voices are busy, so player_hurt or boss_roar is lost behind 8 'hit's. The 30 ms merge drops duplicates instead of reinforcing them, using wall-clock performance.now(). Every sound has the same 0.3 gain (no caller passes the volume parameter). There are no categories, priorities, ducking or reverb sends, only a master DynamicsCompressor (-10 dB, 6:1).
- Spatialization is a one-liner in RenderFx.sfx: pan = clamp((x - player.x)/500, ±0.7). It ignores y, applies no distance attenuation (an off-screen Bone Archer 1500 units away is as loud as one adjacent) and listens from the player, not the camera (renderer.camX/camY). Many emitters pass no x (player_hurt, level_up, every boss roar in enemyAi.ts), so they play dead-centre.
- Presentation randomness uses Math.random (pitch jitter in Audio.play, hat noise in Music), and zzfxBuild ignores its randomness parameter. Audio output cannot be reproduced or snapshot-tested, and no audio PRNG stream sits next to STREAM {layout, enemies, loot, cards, events, shop} in core/rng.ts.
- There is no audio accessibility. Settings v1 has only volMaster/volSfx/volMusic: no captions, no visual indicators for off-screen threats, no mono, no night/dynamic-range mode and no separate UI or ambience sliders. RenderFx.haptic maps 3 hard-coded HapticKinds that are not tied to the sounds.
- There are no audio tests. tests/ covers gen, sim and perf only, and Audio needs `window`, so nothing checks clipping, silence, determinism, voice limiting or which sounds the sim emits. The README notes per-sound and per-note node allocations as a known deviation, and they are never measured.

### UX, onboarding, accessibility & localization

- No onboarding. The only teaching is Hud.showHints(): a static keycap strip shown in the floor-0 start room and hidden by a fixed 15 000 ms setTimeout in app.enterRoom, whether or not the player has moved or attacked. Nothing teaches dash i-frames (CONFIG.dash.invuln 0.22 s), the 0.8 s wave telegraph, the orange windup flicker, AoE telegraph circles, door-based node routing, stat allocation, the +35% card tag weighting, the forge, or gem-to-soul conversion. MetaSave only tracks runs, wins and bestFloor, so there is no first-run or 'seen' flag to build on.
- Input is hard-wired. Input.onKeyDown and sample() hardcode WASD/arrows/Space/Shift/E/F/Tab/M/Q/P, and KeyE means both Interact (gameplay) and tabR (menus). pollGamepad hardcodes button indices 0/1/2/4/5/7/8/9. Nothing can be remapped or saved. Prompts are literal strings in hud.ts ('SPACE', 'SHIFT', 'A', 'B', and a blue 'X' keycap), so PlayStation players see Xbox letters, Switch Pro players see the wrong face buttons, and AZERTY players are told 'WASD'. There is no gamepaddisconnected handler, so losing a controller mid-boss does not pause. The deadzone is per axis (the ax() lambda), which makes a cross-shaped dead zone.
- Fire on KB+M is hold-only. sample() sets o.fire = this.lmb and forces autoAim/aimAssist to false for keyboardMouse, so a 20–30 minute run means holding LMB the whole time. There is no hold-vs-toggle option for any action, no keyboard-only aiming, and touch has only a leftHanded mirror: no one-thumb layout, fixed-stick option or button placement.
- Photosensitivity and motion risks. styles.css never uses prefers-reduced-motion. Several things flicker above WCAG 2.3.1's 3 flashes/s: the player invuln blink (Math.floor(time*20)%2 ≈ 10 Hz), hazard telegraphs (sin(time*30) ≈ 4.8 Hz), spawn rings (≈4 Hz) and enemy windups (sin(time*30)). A boss kill fires flash(0xffffff, 0.6) full-screen, and every player hit flashes crimson. Only screen shake can be turned off; banner zooms, bats, pulses and the rotating map ring always animate.
- Readability depends on color. Phantom dagger glow 0x5ec8ff is nearly the same hue as Rune Colossus bolts 0x4fd8ff (friend vs foe). Telegraph stroke 0xff6a3a and fill 0xff8a2a sit on red carpet 0x9a1630 and brown floors with poor contrast. Soul orbs 0x3ddc84 and heart pickups 0xff4d6a are a red/green pair. In-world chest rarity is shown only by trim and glow color. There are no colorblind modes and no high-contrast enemy-bullet option.
- Text is too small on phones. uiScaleFor clamps at 0.75, so a 390-px-tall landscape phone gets a 12 px root. That puts .card .tag (0.62rem) at 7.4 px, .shop-item .s (0.7rem) at 8.4 px and .card .desc at 9.4 px. uiScaleAdj only allows ±25%. Damage numbers are BitmapText at fixed 15/22 world units and ignore every setting.
- You can't look things up. Tags such as [ORBIT] and phrases like 'per [ORBIT] tag', 'burn stacks' and 'always crits' are never explained. Pause → Cards shows mini-cards with only an icon and name, so you can't re-read what an owned card does mid-run. The character sheet uses unexplained abbreviations ('Cooldown red.'). There are no tooltips anywhere, and no equip comparison with deltas.
- No damage attribution. hurtPlayer() receives an attacker index, but projectiles and hazards pass −1 and nothing is recorded. The end screen shows kills and damage dealt but never what killed you or which sources did your damage.
- Localization is not possible yet. Every string is an inline literal: about 150 in screens.ts, plus hud.ts INTERACT_LABEL, app.ts toasts, NODE_NAME, FLOOR_THEMES, and the data names and descriptions in cards/equipment/economy/classes/enemyDefs/stats. <html lang> is fixed to 'en'. Plurals are hand-written ('point${left===1?'':'s'}'). formatNum hardcodes 'k'/'m'. The Pixi BitmapFont is installed with ASCII chars [' ', '~'] only. The 0.32rem -webkit-text-stroke on the Arial Black stack would smear CJK text.
- Menus and settings don't scale and are invisible to screen readers. Nav only toggles a .focus class and never moves DOM focus. Screens have no role=dialog or aria-labelledby, toasts are not aria-live, settings labels aren't tied to their controls, and toggles lack aria-pressed. Settings v1 is a flat 16-row grid with no categories, descriptions, presets, reset or migration. The quality <select> only cycles forward on confirm. Auto-detection (30-frame refresh measure plus a 6-frame GPU bench) runs silently at boot, so the first time a player hears about quality is a mid-combat toast: 'Quality lowered to MEDIUM'.

### Engineering, performance, platform & tooling

- Orchestration is a god object. src/app.ts (871 lines) holds boot, an implicit 7-string state machine, all menus, the run lifecycle, quality switching, saving and every game rule that runs outside a sim tick: cardRng, chest/shrine/merchant/anvil/campfire/altar resolution, applyEvent, offerItem and nextFloor (L603-869). These rules change Player directly from DOM callbacks (p.scrap -= e.price, p.metaAttrs.vit -= ..., item.level++), so they cannot run headless and cannot be unit-tested, recorded or replayed. The sim talks to the app only through World.events, an array of object literals drained with splice(0) and covering 7 event types. No kill, hurt, pickup or card stream exists for a codex, achievements or run stats to subscribe to. world.ts (1,055 lines) has one hard-coded update order, and enemyAi.ts runs a single switch (d.ai) per enemy.
- Combat is not reproducible across devices, even though the docs claim 'any run is reproducible from its seed'. planSpawns(room, floor, enemyCap) folds surplus enemies into an hpMul using CONFIG.enemyCap[preset] (ultra 400 / high 300 / medium 150 / low 80), and App.applyPreset rewrites world.enemyCap during thermal step-down mid-run. So the same daily seed produces different waves on a phone and on a 4K desktop. Sim code calls Math.random (playerCombat.ts:137 and :317). Cosmetic embers draw from the gameplay w.rng (world.ts:931/949, enemyAi.ts:28), so particle density is coupled to crit rolls. There are about 80 transcendental Math.sin/cos/atan2/hypot/exp call sites in game/, plus Math.sin/cos in gen/poisson.ts and Math.pow in the xpReq curve. The spec does not guarantee these give bit-identical results across V8, JavaScriptCore and SpiderMonkey. No test hashes world state; sim tests only check for no exceptions and finite positions.
- Nothing records inputs or decisions. Input.sample() builds an Intent every tick and throws it away. Card picks, purchases, forge upgrades and event choices happen in UI closures. A bug report can carry only a seed label, which rebuilds the map but cannot reproduce a death to Count Vlador's blood spiral.
- Saves have no versioning or integrity checks. MetaSave, RunSave and Settings carry version: 1, but no migration code exists. Boot does a shallow merge ({...defaultMeta(), ...saved}), so a new nested statBonus attribute would load as undefined and become NaN. There is no checksum, no atomic dual-slot write, no navigator.storage.persist(), and the in-memory fallback in db.ts is silent. Continue-run drops room state: interactable 'used' flags are not saved, so you can rest at the Sanctuary Fire, quit and continue, and the fire is lit again (+35% HP each time). The same works for re-resolving a Mystery altar's +stat-points event. Unopened boss and room chests disappear on continue. Shop 'sold' flags live only in App.shopCache. Player.fromSave restores metaAttrs from meta.statBonus, which erases the Cursed Item's VIT penalty.
- The render path uses per-entity vector Graphics. Each enemy view is about 9-10 display objects (root, shadow, aura, bodyWrap, body, flash, wings/club/runes, hp container, bar, fill), so 400 Blood Bats means about 3,600+ nodes, and Pixi's batcher copies every small Graphics' vertices each frame. makeEnemyView builds a new GraphicsContext for every elite aura, which breaks the build-once rule. Views are destroyed and recreated when a pool slot changes def mid-fight. Projectiles, pickups and hazards are one Graphics per slot. RoomView tessellates whole 60x40-tile rooms on entry. The renderer prefers WebGL (['webgl','webgpu','canvas']) and never tries WebGPU first. App.benchmark() relies on the WebGL-only gl.finish(). Bloom is a BlurFilter at quality 2. The '120 FPS at 4K' acceptance criterion has never been measured.
- Presentation code allocates every frame, against the spec's 'heap flat across a 10-minute run'. Hud.update builds about 12 closures plus template strings each frame through set(key, v, () => ...). The sim builds damage strings (dmg + '!', String(dmg)) on every hit for fx.text. GameRenderer.text and lightning use .find/.reduce closures, and lightning re-tessellates a Graphics for every chain. Every SFX builds a new source, gain and panner graph, and every music note builds its own nodes. PerfMonitor runs slice().reduce() every 2 s. World.loadRoom reallocates the flow and flowQueue arrays for each room. Heap growth has never been measured.
- No tooling backs these rules up. There is no .github CI, no linter, no bundle budget check (only chunkSizeWarningLimit: 1200 against the 1 MB rule; today's build is about 255 KB gz with 174 KB in index), and no guard enforcing zero raster or audio files. The headless playthroughs mentioned in the README are not in the repo; there are no Playwright or screenshot tests. Nothing validates content: 27 cards, 21 items and 5 events reference icons, hooks and card ids by string. perf.test.ts only asserts that a tick takes under 4 ms. The renderer uses Math.random for shake, particles and jitter, so screenshot diffing is not possible today.
- Platform support is incomplete. Icons are SVG only, and apple-touch-icon points at icon.svg, which iOS ignores. The service worker's cache name uses Date.now(), so every build invalidates the whole offline cache even when nothing changed. The SW is cache-first with no update prompt, so players can be stranded on an old build. There are no Capacitor or Tauri wrappers, and no host abstraction for haptics, fullscreen, keep-awake or file share. Key codes are hard-coded in input.ts and only standard-mapping gamepads are handled. The spec's §2.F real-device matrix (iPhone, budget Android, iPad, 4K/144 Hz, Xbox/PS pads) has never been run.
- Debugging support is thin. ?debug=1 only exposes window.__ck. There is no console, no cheats, and no overlay for the flow field, hitboxes, spatial-hash cells, AI states or pool occupancy. The only error handling is a boot-failure message, and an exception inside the 120 Hz loop is lost. SpatialHash.query silently stops at the 256-entry World.queryBuf. Aim assist queries a 520-unit radius (about 18x18 cells of 64 units), so at 300-400 enemies it can drop candidates with no diagnostic.
- There is no balance tooling. Tuning relies on hand play. Nothing measures boss time-to-kill (Gorehorn, Rune Colossus, Vlador), damage taken per enemy or per attack pattern (Axe Armor charge, Hex Witch bolts, rockfall), card win-rate lift (Singularity Core, Storm Chain), or gem economy against shop prices (30-130 x (1+0.25·floor)). hurtPlayer() takes an attacker slot but no attack-pattern source, so deaths cannot be attributed.

### Narrative, lore & quests

- The whole story today is about six hard-coded strings: the FLOOR_THEMES subtitles in theme.ts, five room-entry toasts in App.enterRoom, one win line and one loss line in screens.endScreen ('The Count is no more. Dawn breaks over the keep.' / 'Your soul returns to the castle gate...'), and the boss name in the bossSpawned banner. The game never says why the hunters are there or what Count Vlador wants. The class blurbs in classes.ts only describe mechanics, and the names left over from the spec ('Vector Vanguard', 'Code Weaver', 'Core Reactor', 'Sub-Routine', the internal 'scrap' currency) have no in-world explanation.
- There are only 5 mystery events, each a single page (EVENTS in game/economy.ts). pickEvent uses rng.pick(EVENTS) with no filter for floor, class, history or repeats. A player who seeks out Mystery nodes sees 3-4 per run, and 4 picks from 5 events give an 81% chance of a repeat. EventEffect has 10 one-shot effects and nothing else: no branches, follow-up pages, conditions, ambushes, curses or consequences that carry across runs.
- Two event bugs in App.applyEvent. (1) 'gamble' rolls cardRng(91), which hashes runSeed/attempt/floor/player level/cards.size instead of STREAM.events plus the room seed, so two gambles at the same level and card count on one floor always land the same way. (2) 'cursedItem' says '-10 max HP (permanent)' but subtracts ceil(10/15) = 1 VIT, which is -15 HP, from p.metaAttrs. PlayerSave does not store metaAttrs and Player.fromSave rebuilds them from meta, so the curse disappears on Continue Run.
- There is no dialogue system and no NPC talks. The Wandering Merchant (props.drawMerchant) is a mute prop with one borrowed line in shopScreen ("Heh heh... what're ya buyin'?"). World.loadRoom always spawns the same 'altar' interactable in event rooms, even when the event is a ghost or a fountain. renderer.portrait() only accepts a ClassId, so NPCs and bosses have no portraits. The HUD can only show toast() and banner().
- Bosses have no personality. bossSpawned and bossDefeated only trigger a banner and a roar. There is no intro, taunt, phase line or defeat line, so Gorehorn's two heads, the Colossus's blue rune and Vlador's vampire character come through only in the art.
- No narrative state persists. MetaSave v1 in meta.ts stores souls, classes, packs, statBonus, runs, wins, bestFloor and history, and nothing else: no flags, quest progress, lore read, kills per enemy type or endings seen. App.boot loads it with a shallow {...defaultMeta(), ...saved} merge and has no migration path. Player.kills is one counter, so a bestiary has nothing to build on.
- There are no lore pickups and no codex. RoomMap.decor (bones, skull, coffin, window, banner, candelabra) is purely visual. InteractKind has no readable type. Neither the main menu nor the pause tabs have a Codex or Bestiary, and meta.history (the last 20 seeds) is never used in the story.
- There is only one ending. On the final floor the portal calls App.nextFloor, which calls endRun(true) unconditionally. The player gets no choice when Vlador dies, there are no ending variants, no true ending, no epilogue and no post-game hook, and all 3 classes get the same victory text.
- The game has no story framing. First-room hints disappear after 15 s. There is no prologue. The floor change in nextFloor is a 400 ms fade plus a banner. Death gets one generic line, and the World 'died' event does not record what killed the player.
- Every player-facing string is an inline literal spread across economy.ts, screens.ts, app.ts and hud.ts (INTERACT_LABEL). There is no string table, no length limit and no text test. Growing this to about 100 KB of story text would break phone layouts at 640x360 and block localization.

### Social, multiplayer & community

- Seed labels don't round-trip. The end and pause screens show `seedToString(seed)-attempt` (e.g. "0K3J9QZ-2"). The seed screen (maxlength 9) passes the text to `seedFromString`, which uses parseInt base-36. That stops at the '-', so the attempt silently becomes 0 and a friend lands in a different castle. 8-9 character inputs pass 2^32 (36^9 ≈ 1e14) and get truncated by `>>>0`, so the code shown afterwards differs from what was typed. Vanity words like "BAT-CAVE" only parse the prefix "BAT", so different words collide. There is no clipboard, navigator.share, QR or link anywhere in src/.
- The `?autostart=<class>&seed=` deep link (app.ts boot) skips the title, so `audio.unlock()` never runs from a user gesture: iOS players arriving by link get a silent run. The link can't carry an attempt, rules, class lock, target score or a challenger name.
- The same seed is not the same run for different players. `offerCards` and `shopStock` filter the card pool by `meta.packs` (Holy/Blood/Reaper unlocks), and `Player.metaAttrs` adds up to +5 per stat from meta. `planSpawns` folds surplus enemies by `CONFIG.enemyCap[preset]` (80 on low, 400 on ultra), and `applyPreset` rewrites `world.enemyCap` mid-run when the thermal step-down fires. So 'Daily Moon' is not a fair shared challenge. It is just `hashString('daily:'+Y-M-D)` with unpadded month and day, and 'Retry' increments the attempt (a different castle) while staying flagged daily.
- There is no command or replay layer. `Input.sample()` already produces a clean per-tick `Intent`, but every menu decision mutates state directly in DOM closures in app.ts: onInteract (shop `p.scrap -= e.price`, forge `item.level++`, campfire, shrine, altar), the openLevelUp card pick, `statPanel` writing `p.attrs`, `offerItem` equip/salvage, and the `applyEvent` gamble. None of it is tick-stamped or recorded, so no run can be replayed, raced or verified. tests/sim.test.ts only smoke-tests and never asserts that the same inputs give the same state hash.
- Determinism is fragile. `World.rng` (one stream per room) is shared by gameplay rolls (crit, ±8% damage variance, drops, AI timers) and cosmetic draws (the enemyAi.ts ember `w.rng.next() < dt*10` and smoke puffs), so any VFX tweak reshuffles combat. playerCombat.ts uses `Math.random()` inside the sim tick for dash-trail particles. The sim relies on Math.sin/cos/atan2/hypot/pow/exp, whose last bits differ across V8, JavaScriptCore and SpiderMonkey, so cross-browser replays can drift. Nothing records a sim version or ABI (RunSave is just `version: 1`).
- Continue Run allows save-scumming. `saveRun()` fires on pause, visibility change and pagehide with `roomCleared=false`. `continueRun` then reloads the room: the boss is back to full HP and the player gets refilled energy and cooldowns and a rounded `hpFrac`. Quitting mid-Vlador resets the fight. `Player.fromSave` also rebuilds `metaAttrs` from meta, which silently drops the Forgotten Armory's −VIT curse. That's tolerable for casual play but breaks any ghost or leaderboard.
- Single-player is hard-wired. `World.player` is read about 25 times: `updateFlow` runs its BFS from one tile, enemyAi does `const p = w.player`, and hurtPlayer, collect, updateInteractables and checkExit all assume one player. `Input` tracks one `padIndex`, one key Set and one pair of virtual sticks split by screen half. `GameRenderer` has one `playerView`, and the camera (camX/camY damp plus a 40-unit aim look-ahead) follows only `w.player`. Hud, Nav (one `current` focus) and RunSave are single-player too.
- There's no photo or spectator camera. The camera is clamped to the room with a fixed zoom from `viewTilesW` = 24, and shake uses Math.random. The DOM HUD can be hidden, but there is no free cam, pose or capture. `renderer.portrait()` already uses `app.renderer.extract.canvas`, which is reusable for runtime screenshots.
- Content is closed TypeScript. ENEMY_DEFS (numeric ids stored in a Uint8Array `def`), CARDS, ITEMS, EVENTS, CLASSES and FLOOR_THEMES are const arrays. AI is a closed union (chase/flutter/ranged/caster/charger/boss), hooks are a closed `HookKey` union, and enemy art is bespoke `draw*` functions in render/art/characters.ts. screens.ts has 20 `html:` innerHTML sinks. There's no schema, registry or content hash, so modding is impossible and nothing identifies the content set in a replay.
- Nothing faces streamers or the community. `Run.elapsed` is an exact in-game time but appears only on the end screen. There are no splits, no spoiler-safe seed hiding, and no export of stats. `meta.history` keeps only 20 records (seed, attempt, class, result, floor, date): no score, time, build or cause of death.

### Game design, balance & difficulty

- No balance instrumentation. tests/sim.test.ts only checks that the sim does not crash: a random-walk bot with 1e6 HP, and bosses still alive at 1% player damage. Nothing asserts win rate, time-to-kill (TTK), damage taken or gem flow, so every number in src/config.ts is tuned blind. I wrote a naive kite-and-auto-fire bot (throwaway scratch script, 20 seeds per class, floor 1 only). It died to Gorehorn in 54 of 60 runs (the Code Weaver about 11-18 s into the fight), and more than half of its battle rooms hit a 180 s timeout. The game has no competent bot that could produce usable numbers.
- Classes are far apart at level 1. Phantom Blade's twin daggers do (9+2)x2/0.26 s = about 85 DPS (about 94 with 18% crit). Vector Vanguard does about 58 (26/0.46 s) and Code Weaver about 48 (16/0.34 s). The Weaver also has the lowest HP (70) and armor (2). On floor 3, one contact from an elite Axe Armor deals about 50 damage (22 x floorDmgMul 1.64 x elite 1.4) to her.
- Card power is not normalized, and stacks have no cap. Forked Vector (rare) adds two 45% shards per hit: about +90% single-target DPS if the shards land. Reaper's Scythe hits for 2.5x base damage and always crits. Requiem hits every enemy in the room, off-screen ones included, for 4x base every 12 s. Split Volley is +100% for Weaver (1 to 2 orbs) but only +50% for Phantom (2 to 3 daggers). Burning Hex is a flat 5 dps per stack, which barely matters against a floor-3 Skeleton with 71 HP. offerCards has no max-stack filter and no pity rule.
- Card-offer RNG repeats. app.ts cardRng(77) is salted only by level and the number of distinct cards owned, and chests and Blood Shrines both use it. A shrine opened after a chest at the same level shows the identical 3 cards. Picking a stack of a card you already own does not change cards.size, so the repeat persists. The Fortune Skull gamble uses cardRng(91), which is the cards stream rather than STREAM.events.
- Pacing is boss-heavy and the XP curve does not match the content. I sampled 300 seeds of the generator on uniform-random paths. A path has only about 2.5 combat or elite rooms per floor. Bosses are 80% (Gorehorn 2,400 HP), 75% (Rune Colossus 4,200) and 69% (Count Vlador 6,000) of each floor's total enemy HP. The player is level 3 after floor 1 and level 5 after floor 2, and fights the Count at about level 5. That is only about 4 level-up card picks per run. The Count's 1,800 XP arrives after the run is decided, and with 100*L^1.45, level 10 needs 10,122 cumulative XP, which current content cannot reach.
- The economy leaks and its incentives conflict. soulsFromRun uses unspent gems (floor(scrap x 0.5) + 10 per floor + 60 on victory), so every shop or forge purchase costs meta-progress. killEnemy gives bosses the same 30% gem roll as a Skeleton, so Gorehorn's 60-gem hoard is a coin flip. Boss summons (Count bat swarms of 5-7, Gorehorn skeletons) award full XP and gems, so a stalled fight can be farmed. The shop and rest guarantees are per floor, not per path: a random path meets a shop on only about 47% of floors and a rest on about 75%. Rest rooms give both the campfire and the anvil, so there is no choice to make. The Cursed Armory says '-10 max HP (permanent)' but actually removes 1 VIT from metaAttrs (-15 HP, -0.5 regen), and Player.fromSave re-applies meta.statBonus, so the curse disappears after Continue.
- Several attacks break basic fairness. After Count Vlador vanishes, his hellfire fires on the first tick after he reappears 220 px away: fireT was zeroed and t=1.0 drops below 1.0 on the next tick, so there is no windup tell. The Rune Colossus rune burst (state 4) and enrage spiral (state 7) also fire on their first tick. Bone Archer and Gargoyle windups are only 0.35 s. Ranged enemies hold 170-320 px and fire at up to 480 px with line of sight, while the guaranteed half-view height is 216 px (13.5 tiles), so they shoot from off-screen. Wave 2 and 3 spawn points are chosen at plan time relative to room.spawn, not the player's current position, so enemies can rise next to the player with about 1.15 s of warning. No per-hit damage cap exists.
- Rooms stall. The Blood Bat swoop AI ('flutter' in enemyAi.ts) and flying ranged enemies without line of sight steer straight at the player and pin themselves against walls; they never use flowDir. In the bot experiment, 325 of the 326 enemies still alive at room timeout were Blood Bats with no line of sight to the player. Auto-aim requires line of sight, and the 14 s wave timer only starts new waves; nothing resolves the last stuck enemy.
- Controls feel unforgiving. Input latches are cleared after every 120 Hz tick (Input.consumeEdges), so a Dash or ability pressed even 1 tick before it is ready is dropped. Aim assist hard-snaps to the nearest enemy in a 12 degree cone with no line-of-sight check and no hysteresis, so it can retarget every tick. One shared acceleration constant (dt x 16) handles both speeding up and stopping. There is no hit-stop and no knockback weight classes: bosses take 0.08x knockback, elites 0.5x, everyone else 1x.
- Difficulty is one size for everyone and elites are bland. The only difficulty knobs are floorDifficulty [1, 1.55, 2.2], floorHpMul 1+0.55f and floorDmgMul 1+0.32f. There are no modes, heat levels or assist options. Elites are plain stat boosts (x3 HP, x1.4 damage, x1.3 size) with no affixes, and bosses have one 40% enrage instead of phases. planSpawns takes the quality-preset enemyCap (low 80 to ultra 400) and folds surplus enemies into an HP multiplier. That never triggers at today's budgets, but daily seeds would play differently by device once budgets grow.

### Gaps found in review

- Device-dependent simulation: World is built with CONFIG.enemyCap[preset], which ranges from 80 on Low to 400 on Ultra (app.ts:353/365). applyPreset() rewrites world.enemyCap mid-run on a thermal step-down (app.ts:165), and spawner.ts planSpawns folds surplus enemies into an hpMul. The same seed already plays differently on a phone and a desktop, before dailies, ghosts or replays exist.
- Unregistered PRNG streams: STREAM in core/rng.ts lists only 6 streams. graph.ts:32 uses its own salt 0x6a09e667 and World.loadRoom uses 0xc0b4a7. Card offers are seeded inside app.ts:605 from player level and cards.size, and altar rolls reseed from Math.floor(it.roll*1e6) (app.ts:656). Seven planned epics add more streams, and none has an owner.
- Cross-engine math: poisson.ts:57-58 places spawns with Math.cos/Math.sin, and about 69 lines in src/game use trig functions. ECMAScript leaves these implementation-approximated (V8 and SpiderMonkey use fdlibm, JavaScriptCore uses the system libm), so Safari and Chrome are not guaranteed to produce bit-identical layouts or combat.
- Contracts every epic wants to change: Intent has four booleans (fire, ability, dash, interact). FxSink.text() takes a string, so every hit allocates (world.ts:482/591/627), and colours are raw hex. SfxName is a closed 20-member union. WorldEvent creates heap objects. app.ts handleEvents mutates the World (w.spawnBossRewards()) and owns time scale (loop.timeScale 0.35/0.3), so hit-stop has no deterministic home.
- Store headroom: POOLS.hazards is 64, with 6 HAZ kinds in use. ProjectileStore.flags is a Uint8Array with 6 of 8 bits taken (PF_LOB = 32). EnemyStore.def is Uint8, which caps enemy IDs at 256.
- No version identity: RunSave, MetaSave and Settings are all `version: 1`. Seed labels are `${seed}-${attempt}`, and the daily seed is hashString('daily:'+date). Nothing distinguishes a seed made by one generator from a seed made by a later one.
- Touch thumb collision: input.ts splits the screen in halves (left moves, right is the floating aim stick), and hud.layoutTouch puts Skill, Dash and Interact on the aim side. The right thumb already aims and presses three buttons, and nothing reserves room for the 4–5 actions other epics add.
- Art throughput: characters.ts spends about 45 lines per rig across 13 rigs and uses 116 raw hex literals (58 unique) against 59 THEME token references. pen.ts applies OUTLINE = 3 at every size, from bat to boss. The only reused part is the local skull() helper.
- Naming drift has started: the in-run currency is `scrap` in code (Player.scrap, CONFIG.scrapToSouls, soulsFromRun) but 'gems' on the HUD. Boss and floor names are string literals spread across enemyDefs, theme.ts and world.bossName.
- Licence compliance: the repo has no LICENSE file. The production dist/ strips both the PixiJS and the vendored ZzFX MIT notices: no 'MIT' or 'Frank Force' string appears in dist/assets/*.js.
- Security: index.html has no CSP. dist contains 5 `new Function` sites from PixiJS v8 codegen, so a strict CSP needs the pixi.js/unsafe-eval polyfill. `?debug=1` exposes window.__ck in production builds. ui/dom.ts's `html` prop feeds innerHTML at about 28 call sites in src/ui, and hud.ts templates the prompt and hints with innerHTML.
- Release safety: the generated sw.js calls skipWaiting() and clients.claim() with a Date.now() cache name, so a new deploy takes over open tabs mid-run. There is no save downgrade guard, no feature flag system and no archived builds.
- Lifecycle: renderer.ts has no webglcontextlost/restored handling, and there is no window-blur auto-pause. Continue-run is room-granular (only a roomCleared flag), and Rng keeps its state private, so mid-room snapshots are impossible. loop.ts silently zeroes the accumulator after 30 catch-up steps. There is no 30 FPS tier, although the spec's Low row says '60 (30 floor)'.
- Test coverage is three vitest files (gen, sim, perf). There are no modal-flow regression tests, no browser, CSP or cross-engine runs, and no golden seed corpus.
- SKIPPED – Platform services bridges (Steam Cloud and achievements, Game Center/iCloud, Play Games): deferred to post-1.0 in PRD-1's roadmap. They need TEC-8 wrappers and MET-6 achievements first, add nothing to the backend-free web build, and Soul Sigil export plus local achievements cover 1.0.
